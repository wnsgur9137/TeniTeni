# 08. 로드맵과 리스크

> 단계 내부의 순서·선행 관계·병렬화는 [작업 순서](WORK-PLAN.md)를 참고하세요.

|---|---|---|---|---|
| **0** | 기술 검증 프로토타입 | ✗ | 3~5주 (게이트 판정은 1.5주) | **공 궤적 검출률 70%** |

| **3** | 코트 분석 + 레퍼런스 비교 | ✓ | 6주+ | — |

### Phase 0 — 기술 검증

**목표: 이 앱이 기술적으로 가능한지 판정한다.**

상세 순서와 선행 관계는 [작업 순서 9.3](WORK-PLAN.md#93-phase-0--기술-검증)에 있습니다.

| 단계 | 장소 | 내용 | 기간 |
|---|---|---|---|
| **[0-A](https://github.com/wnsgur9137/TeniTeni/milestone/1) 정찰** | 책상 | 포맷 덤프·화각 실측, **최소 촬영 앱**(포맷/노출 고정 + 녹화만) | 2~3일 |
| **[0-B](https://github.com/wnsgur9137/TeniTeni/milestone/2) 촬영** | 코트 | 조건별 영상 세트 확보 (fps·노출·거리·배경 변주) | 1일 |
| **[0-C](https://github.com/wnsgur9137/TeniTeni/milestone/3) 검증** | 책상 | VisionKit 분리, macOS CLI 분석·라벨링 도구, 파라미터 스윕 → **게이트 판정** | 1주 |
| **[0-D](https://github.com/wnsgur9137/TeniTeni/milestone/4) 파이프라인** | — | **게이트 통과 시에만.** Metal·스켈레톤·One Euro·실시간·발열·동시성 | 2~3주 |

**게이트를 앞으로 당긴 이유**: 궤적 검출률은 오프라인으로 재도 같은 값입니다. 영상을 찍어두고 나중에 돌리면 파라미터를 바꿔가며 반복 측정할 수 있고, 코트에 여러 번 나가지 않아도 됩니다. 반대로 Metal 렌더·스켈레톤·One Euro는 검출률 측정과 **무관**합니다. 게이트가 실패하면 그 작업이 무의미해지므로 뒤로 미룹니다.

이 배치로 **게이트 판정이 3~5주 뒤 → 1.5주로 앞당겨집니다.**

백엔드 코드는 한 줄도 쓰지 않습니다.

> **게이트: "실외 맑음 · 단순 배경 · 120fps · 1/1000s · 6m" 조건에서 궤적 검출률 70%.**
> 가장 유리한 조건에서도 미달이면 접근 방식이 잘못된 것입니다.
> 50~70%면 재튜닝 후 재측정, 50% 미만이면 서버 TrackNet 전환 또는 궤적 기능 v1 제외를 판단합니다.

### 상세: R-2 카메라 흔들림

`DetectTrajectoriesRequest`는 **고정 카메라가 전제**입니다. 손으로 들고 찍으면 궤적 검출이 완전히 무너집니다. 이건 튜닝으로 해결되지 않습니다.

따라서 기술 제약을 제품 요구사항으로 승격시킵니다:
- 온보딩에서 삼각대 사용을 명시적으로 안내
- 촬영 화면에 권장 거리/각도 프레이밍 가이드
- `CMMotionManager`로 흔들림 감지 → 실시간 경고 배너
- 흔들림이 임계값을 넘으면 궤적 기능을 자동 비활성화하고 이유를 표시

### 상세: R-3 자세 평가 신뢰도

"이 스윙 87점"을 ML로 만들려면 점수 라벨 데이터셋이 필요한데, 존재하지 않습니다. 게다가 프로 선수들의 폼도 서로 크게 달라 정답이 하나가 아닙니다.

대응은 [03. 비전 파이프라인](../02-설계/VISION-PIPELINE.md) 3.6절의 3단계 접근입니다. 핵심은 **틀릴 수 있음을 인정하는 UX**입니다. 신뢰도가 낮은 지적은 단정형으로 표현하지 않습니다.
