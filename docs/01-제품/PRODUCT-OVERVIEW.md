# 01. 제품 개요

## 1.1 제품 정의

**TeniTeni** — 스마트폰 카메라만으로 테니스 스윙 자세를 분석해 교정 피드백을 제공하고, 공의 궤적을 추적·시각화하는 iOS 앱.

한 문장 요약:
> 삼각대에 아이폰을 세워두고 연습하면, 스윙마다 자세를 분석해 무엇을 고쳐야 하는지 알려주고 공이 어디로 갔는지 보여준다.

## 1.2 해결하려는 문제

아마추어 테니스 플레이어는 다음 상황에 놓여 있습니다.

- 자신의 스윙이 어떻게 보이는지 모른다. 영상을 찍어도 **무엇이 잘못됐는지 판단할 눈이 없다**.
- 레슨은 비싸고 주 1회가 한계다. 나머지 6일의 연습은 피드백 없이 진행된다.
- 공이 아웃된 이유(라켓 면? 체중 이동? 임팩트 지점?)를 스스로 연결하지 못한다.

TeniTeni는 **레슨과 레슨 사이의 피드백 공백**을 메우는 것을 목표로 합니다. 코치를 대체하지 않습니다.

## 1.3 타깃 사용자

| 구분 | 설명 | 우선순위 |
|---|---|---|
| 주 타깃 | 구력 6개월~3년의 아마추어. 폼을 교정하고 싶지만 혼자 판단이 안 되는 층 | 1순위 |
| 부 타깃 | 코치. 레슨 중 학생에게 즉석 시각 자료로 활용 | 2순위 |
| 제외 | 프로/세미프로. 요구 정밀도가 다르고 이미 전용 장비를 씀 | — |

## 1.4 핵심 유스케이스

### UC-1. 혼자 연습하며 스윙 촬영
1. 삼각대에 거치 → 앱 실행 → 카메라 배치 가이드에 맞춰 정렬
2. 촬영 시작. 화면에 **실시간 스켈레톤 오버레이**와 **공 궤적 트레일** 표시
3. 스윙이 감지될 때마다 자동으로 구간 기록
4. 촬영 종료 → 세션 요약 (스윙 N회, 유형별 분포, 평균 점수)

### UC-2. 스윙 리플레이로 자세 확인
1. 세션 내 스윙 목록에서 하나 선택
2. 슬로우 모션 재생 + 스켈레톤 + 페이즈 구분(준비/테이크백/포워드스윙/임팩트/팔로스루)
3. 문제 관절이 빨강으로 표시되고 각도 수치가 함께 노출
4. 텍스트 피드백: "임팩트 시 팔꿈치가 과도하게 굽혀져 있습니다 (112°, 권장 150~170°)"

### UC-3. 공 궤적 확인
1. 스윙 리플레이에 공 궤적이 겹쳐 표시
2. (Phase 3) 추정 구속

### UC-4. 라인 판정 (촬영 중 실시간)
1. 촬영 상황을 **시합**으로, 관찰 대상을 **라인 판정**으로 — 판정할 라인의 연장선에 폰을 둔다
2. 정지 프레임에서 코트 모서리 4점 탭 (세션 1회)
3. 촬영 중 바운스마다 **화면에 즉시** 인 / 아웃 / 판정 불가 표시

> 스윙 분석과 **동시에 할 수 없습니다.** 두 기능이 요구하는 카메라 배치가 정반대입니다 — [ADR-0004](../05-결정/adr/ADR-0004-line-call-mode.md).

### UC-5. 진척도 추적
1. 주/월 단위로 지표 변화 추이 확인
2. 프로 레퍼런스 스윙과 겹쳐 비교

## 1.5 기능 범위

### In Scope (v1)
- 후면 카메라 단일 촬영, **측면 각도 고정** (고정 카메라 전제) — [촬영 프로토콜](../02-설계/CAPTURE-PROTOCOL.md)
- 촬영 품질 선택: 120fps(정밀, 기본) / 60fps(표준)
- 포핸드 / 백핸드 / 서브 / 발리 구분
- 2D 포즈 기반 관절 각도 지표
- 실시간 스켈레톤 오버레이
- 공 궤적 검출 및 시각화
- **촬영 상황 구분** — 볼머신 · 벽치기 · 랠리 · 시합 · 레슨 (상황마다 유효한 룰이 다르다)
- **관찰 대상 분리** — 내 스윙 / 라인 판정 (삼각대 배치가 다르다)
- **실시간 라인 판정** (인 / 아웃 / 판정 불가 3분류)
- 스윙 자동 구간 검출 및 클립 저장
- 룰 기반 자세 평가 및 텍스트 피드백

### Out of Scope (v1)
- 멀티 카메라 / 다중 인물 동시 분석
- **모든 라인 동시 판정** — 카메라 1대로는 한 번에 한 라인
- **Hawk-Eye 급 정밀도** — 공인 시스템은 카메라 10대 이상·340fps. 폰 1대로 도달 불가
- 라켓 면 각도, 스핀량 정밀 측정 (센서 없이 영상만으로는 신뢰도 확보 불가)
- 상대방 분석, 경기 스코어링
- Android

### 검토 대상 (v2+)
- Apple Watch IMU 연동 — 손목 가속도로 스윙 감지 정확도 보강. 차별화 요소로 유력
- 3D 포즈 (`DetectHumanBodyPose3DRequest`) 기반 정밀 각도 — **X-Factor는 여기서 확보**한다. 측면 단일 각도로는 어깨-골반 회전차가 정확히 측정되지 않는다
- 프로 레퍼런스 라이브러리 및 DTW 비교
- 코치용 공유/코멘트 기능

## 1.6 성공 기준

기술적으로 "된다/안 된다"를 가르는 기준을 미리 못박아 둡니다.

| 항목 | 기준 | 검증 시점 |
|---|---|---|
| 스윙 검출 재현율 | 실제 스윙의 95% 이상 감지 | Phase 1 |
| 스윙 분류 정확도 | 4종 분류 90% 이상 | Phase 1 |
| 공 궤적 검출률 | 기준 조건에서 70% 이상 — [측정 방법](../02-설계/CAPTURE-PROTOCOL.md#55-phase-0-게이트-측정-방법) | **Phase 0** |
| 라인 판정 지연 | 바운스 후 100ms 이내 화면 표시 | Phase 1 |
| 라인 판정 정확도 | **미정** — 실측 기준이 없어 Phase 1에서 정한다 | Phase 1 |
| 실시간 성능 | 분석 파이프라인 60fps 유지, 오버레이 드롭 없음 | Phase 0 |
| 발열 | 연속 15분 촬영 시 스로틀링 없음 | Phase 1 |
| 피드백 신뢰도 | 코치 검수에서 "틀린 지적" 10% 미만 | Phase 2 |

> **공 궤적 검출률이 Phase 0의 게이트입니다.** 여기서 기준 미달이면 접근 방식 자체를 재설계해야 하므로, 백엔드를 포함한 다른 작업을 시작하기 전에 반드시 먼저 검증합니다.

## 1.7 용어집

| 용어 | 정의 |
|---|---|
| **세션(Session)** | 한 번의 연습. 촬영 시작~종료까지의 단위 |
| **클립(Clip)** | 세션 중 저장된 영상 파일. 촬영 fps를 함께 기록한다 |
| **스윙(Swing)** | 자동 검출된 한 번의 스윙. 클립 내 시간 구간으로 표현 |
| **페이즈(Phase)** | 스윙 내부 단계. 준비 → 테이크백 → 포워드스윙 → 임팩트 → 팔로스루 |
| **관절(Joint)** | Vision이 추정하는 신체 지점. 2D 19개 |
| **본(Bone)** | 두 관절을 잇는 선분. 스켈레톤 렌더링 단위 |
| **메트릭(Metric)** | 스윙에서 산출된 정량 지표. 예: 임팩트 시 팔꿈치 각도 |
| **X-Factor** | 골반과 어깨의 회전 각도 차. 파워의 핵심 지표. **v1 제외, v2에서 3D 포즈로 확보** |
| **레퍼런스(Reference)** | 비교 기준이 되는 모범 스윙 시퀀스 |
| **궤적(Trajectory)** | 공의 시간에 따른 위치 시퀀스 |
| **호모그래피(Homography)** | 영상 평면 ↔ 코트 평면 변환 행렬 |
| **촬영 상황** | 공이 어디서 오는가. 볼머신·벽치기·랠리·시합·레슨. **어느 룰이 유효한지**를 결정한다 |
| **관찰 대상** | 앱이 무엇을 보는가. 내 스윙 / 라인 판정. **삼각대 배치**를 결정한다 |
| **바운스(Bounce)** | 공이 코트에 닿는 지점. 궤적의 포물선이 끊기는 곳 |
| **코트 프리셋** | 저장해 둔 호모그래피. 같은 코트·같은 거치 위치면 재사용한다 |
