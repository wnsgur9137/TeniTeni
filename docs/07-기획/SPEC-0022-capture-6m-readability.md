# SPEC-0022. 촬영 화면 6m 가독성

> 이슈 [#22](https://github.com/wnsgur9137/TeniTeni/issues/22) · 마일스톤 `0-A 정찰`

## 배경

0-A 촬영 화면이 SwiftUI 기본 색(`Color.black`·`.white`·`.orange`)을 쓰고 있어 [디자인 시스템](../06-디자인/DESIGN-SYSTEM.md)과 어긋납니다. [IA-FLOW 10.5](../06-디자인/IA-FLOW.md)의 6m 가독성 설계도 반영되어 있지 않습니다.

**0-B 코트 촬영에서 이 화면을 실제로 6m 밖에서 씁니다.** 디자인의 핵심 주장이 6m 가독성인데 기본 스타일로 나가면 그 가설을 검증할 기회를 놓칩니다. 0-B는 코트에 나가야 하는 작업이라 다시 하기 비쌉니다.

[SwingVision 조사](../08-레퍼런스/SwingVision.md)에서 같은 문제가 확인됐습니다 — 사용자가 코트에서 카메라 상태를 확인하지 못해 iPad·Apple Watch 미러링을 동원합니다. 우리는 그걸 **멀리서도 읽히는 화면**으로 풉니다.

## 범위

### 만들 것

- 디자인 시스템 토큰 적용 — `bg/scrim` · `text/*` · `state/*` · `accent/primary`
- **녹화 중 설정 숨김** — IA-FLOW 10.5 "수치·설정·피드백은 촬영 중에 표시하지 않는다"
- 경과 시간을 초대형 숫자로 (목업의 스윙 카운트 자리, 72 pt)
- 상태를 화면 테두리 색으로 — 정상 없음 / 경고 `state/warning`
- 72 pt 원형 녹화 버튼 (`CaptureContinuous.dc.html`과 같은 규격)

### 만들지 않을 것

- **스윙 카운트** — 스윙 검출이 [1-B](../04-계획/WORK-PLAN.md)입니다. 0-A에 셀 것이 없습니다
- **소리 설계** — 감지음이 있어야 의미가 생깁니다. IA-FLOW 10.5가 "소리가 화면보다 중요하다"고 하지만 감지할 이벤트가 없습니다
- **스켈레톤 오버레이** — 0-D
- **`DesignSystem` 모듈** — [1-A](../04-계획/WORK-PLAN.md)에 만듭니다. 0-A는 단일 타깃이므로 앱 안에 둡니다
- **목업의 나머지 9개 화면** — 1-A 이후

## 구현 선택지

### 토큰을 어디에 둘 것인가

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 앱 타깃 안 `DesignSystem/Tokens.swift`** | 지금 당장 쓸 수 있다. 1-A에서 모듈로 옮길 때 파일째 이동 | 0-A 범위가 조금 늘어난다 |
| B. `TeniVision`에 넣기 | 이미 모듈이 있다 | **UI를 모른다는 규약 위반.** macOS CLI가 색을 알 이유가 없다 |
| C. 뷰에 하드코딩 | 가장 적은 변경 | 목업과 갈라진다. 두 번째 화면에서 바로 중복 |

**채택: A.** [작업 순서 9.6](../04-계획/WORK-PLAN.md)의 "필요할 때 만든다"를 지키되, 1-A 이동이 `git mv` 한 번이 되도록 디렉터리를 미리 나눕니다.

### 녹화 중 설정을 어떻게 숨길 것인가

| 선택지 | 내용 |
|---|---|
| **A. 완전히 제거** | 녹화 중에는 설정 패널을 렌더하지 않는다 |
| B. 흐리게 | 투명도를 낮춰 남겨둔다 |

**채택: A.** B는 6m에서 "뭔가 있는데 안 읽히는 것"이 되어 오히려 다가오게 만듭니다. 설정은 녹화 중 어차피 잠겨 있습니다 — `CameraController`가 녹화 중 `applyFormat()`을 차단합니다.

### 경과 시간의 표기

**채택: `M:SS`.** 목업이 `12:04`를 보여줍니다. 0-A의 녹화 상한이 600초(10분)이므로 자리수가 넘치지 않습니다.

## 완료 기준

- [ ] `Color.black`·`.white`·`.orange` 같은 SwiftUI 기본 색이 촬영 화면에 남아 있지 않음
- [ ] 토큰 값이 [DESIGN-SYSTEM 11.2](../06-디자인/DESIGN-SYSTEM.md)와 일치 (문자열 대조)
- [ ] 녹화 중 설정 패널이 뷰 계층에서 사라짐
- [ ] 경고 메시지가 있으면 화면 테두리가 `state/warning`으로 바뀜
- [ ] 경과 시간이 72 pt로 표시되고 `M:SS` 형식
- [ ] `scripts/verify-ios.sh` 통과, 경고 0

## 검증 방법

| 항목 | 방법 |
|---|---|
| 게이트 | `scripts/verify-ios.sh` |
| 토큰 일치 | 토큰 파일의 hex와 `DESIGN-SYSTEM.md`의 hex를 대조하는 단위 테스트 |
| 기본 색 잔존 | `grep`으로 `Color.black`·`.white`·`.orange` 확인 |
| 녹화 중 숨김 | 상태별로 뷰를 만들어 설정 패널 유무 확인 |

**6m 가독성 자체는 검증할 수 없습니다.** 실기기를 6m 밖에 두고 봐야 합니다 — 0-B에서 사람이 판정합니다.

## 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **6m에서 여전히 안 읽힌다** | 0-B 촬영이 불편해지고 설계 전제가 흔들림 | 0-B에서 사람이 판정. 72 pt가 부족하면 키운다 — 숫자 하나 바꾸는 일이다 |
| 녹화 중 설정을 못 봐서 불편 | 0-A 실험 효율 저하 | 설정은 녹화 중 어차피 잠겨 있다. 정지 후 보인다 |
| 0-A 범위를 넘어선다 | 버려질 코드에 시간 | 토큰 파일 + 뷰 수정으로 한정. 1-A에서 `git mv`로 재사용한다 |
| 토큰이 문서와 갈라진다 | 목업과 구현 불일치 | 단위 테스트로 hex를 고정 |

## 미수행으로 남길 것

- **소리** — 감지할 이벤트가 없습니다
- **나머지 9개 화면** — 1-A 이후
