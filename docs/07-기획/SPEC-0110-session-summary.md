# SPEC-0110. 세션 요약과 스윙 0개 진단

> 이슈 [#110](https://github.com/wnsgur9137/TeniTeni/issues/110)

## 배경

[SPEC-0097](SPEC-0097-swing-wiring.md)로 세션이 저장되기 시작했는데 **볼 방법이 전혀 없다.** 촬영을 끝내면 홈으로 돌아갈 뿐이고 보관함 탭은 플레이스홀더다. `SessionRepository.load(id:)`와 `loadAll()`은 한 번도 불린 적이 없다.

특히 **스윙 0개로 끝난 세션**이 급하다. [IA-FLOW](../06-디자인/IA-FLOW.md)가 "빈 세션 요약을 보여주면 사용자는 **앱이 고장났다고 판단한다**"고 적었고, [#103](https://github.com/wnsgur9137/TeniTeni/issues/103)의 캡처 풀 문제 때문에 **실기기 첫 시도에서 0개가 나올 개연성이 높다.** 그때 원인을 짚지 못하면 사용자는 무엇을 고쳐야 할지 모른다.

## 목업이 요구하는 데이터가 아직 없다

`SessionSummary` 목업은 **평균 점수(+추이) · 유형 분포 · 가장 자주 나온 문제**를 보여준다.

| 목업 요소 | 데이터 | 상태 |
|---|---|---|
| 스윙 수 | `Session.swingCount` | ✅ |
| 날짜·소요·상황 | `startedAt`·`endedAt`·`situation` | ✅ |
| 클립 목록 | `Session.clips` | ✅ |
| 유형 분포 | `Swing.kind` | ⚠️ 타입은 있지만 **아무도 채우지 않는다**(1-D) |
| 평균 점수·추이 | — | ❌ **모델이 없다**(1-D) |
| 가장 자주 나온 문제 | — | ❌ **모델이 없다**(1-D) |

**없는 데이터를 만들어내지 않는다.** 점수·유형·문제 영역은 1-D 이후에 채운다 — 지금 구현하면 화면이 거짓을 말한다.

## 목업의 자기 모순을 정정한다

`EmptySession` 목업은 "**영상은 저장하지 않았습니다**"라고 쓰면서 바로 아래에 `[방금 영상 확인]` 버튼을 둔다. 저장하지 않은 것을 확인할 수는 없다.

IA-FLOW 본문은 "영상은 지웁니다 — 스윙이 없으면 저장할 가치가 없습니다. **다만 사용자가 직접 확인할 수 있게 한 번은 보여줍니다**"로 적어, 둘의 순서를 의도했다(보여준 뒤 지운다).

그런데 **구현의 현실은 다르다.** `CameraController`는 통영상을 `Documents`에 메타데이터와 함께 저장하고 **아무도 지우지 않는다.** 삭제는 되돌릴 수 없는 동작이라 이 작업 범위에서 뺐으므로, 문구를 사실에 맞춘다 — "영상은 남아 있습니다". 삭제 흐름은 후속 작업에서 다룬다.

## 범위

### 만들 것

- `SessionSummaryFeature` + 화면 — 날짜·소요·상황, 스윙 수, 클립 목록(클립별 스윙 수·시각·fps)
- **스윙 0개면 요약이 아니라 진단** — 확인 항목 3개와 `[배치 다시 보기]`
- 촬영 종료 → 요약 전이. **탭바 없음**(IA-FLOW: 흐름 중간이라 탭 이동이 세션을 끊는다)
- `SessionRepository.load(id:)`의 첫 실제 사용

### 만들지 않을 것

- 점수·유형 분포·문제 진단 — 1-D 의존
- 리플레이(클립 재생), 보관함 목록, 판정 탭
- **영상 삭제** — 되돌릴 수 없다. 별도로 다룬다
- `[방금 영상 확인]` — 재생 화면이 없다. 삭제와 함께 후속

## 구현 선택지

### 1. 요약에 무엇을 넘기는가

| 선택지 | 장점 | 단점 |
|---|---|---|
| `Session` 전체를 상태에 싣는다 | 읽기가 없다 | 보관함에서 들어오는 경로와 **다른 코드**가 된다. TCA 상태에 클립 배열이 들어간다 |
| **세션 id만 넘기고 저장소에서 읽는다** | 촬영 직후와 보관함이 **같은 경로**가 된다(IA-FLOW: "같은 목적지"). 저장이 실제로 됐는지도 이 읽기로 드러난다 | 읽기 실패 경로가 생긴다 — 그것도 보여줘야 한다 |

**채택**: id만 넘긴다. 읽기 실패는 화면에 사유를 남긴다.

### 2. 0개 판정을 어디서 하는가

| 선택지 | 장점 | 단점 |
|---|---|---|
| Feature를 둘로 나눈다 | 화면별로 깔끔 | **같은 로딩 코드가 둘** 생긴다. 어느 쪽을 띄울지는 읽은 뒤에야 안다 |
| **한 Feature에서 분기한다** | 로딩이 한 곳. 읽은 결과로 화면을 고른다 | 상태에 분기가 들어간다 |

**채택**: 한 Feature. 읽기 전에는 어느 화면인지 알 수 없으므로 로딩을 나눌 수 없다.

### 3. 어디에 띄우는가

촬영은 `fullScreenCover`로 탭바를 덮는다. 요약도 **탭바가 없어야** 하므로 같은 층이어야 한다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| `CaptureFeature` 안의 단계로 둔다 | 전이가 한 Feature 안 | 촬영이 끝났는데 촬영 Feature가 살아 있다. 카메라 세션이 요약 동안 떠 있다 |
| **`AppFeature`가 코디네이터로 띄운다** | 촬영을 닫고 요약을 연다 — 카메라가 내려간다. [D-03](../05-결정/stack/D-03-architecture-pattern.md)의 "Feature 간 직접 의존 금지, Application 경유"와 맞는다 | `AppFeature`에 상태가 하나 는다 |

**채택**: `AppFeature` 코디네이터. 촬영 delegate가 세션 id를 들고 올라간다.

## 완료 기준

- [ ] 스윙 0개 세션이 **진단 화면**으로 간다(요약이 아니다)
- [ ] 스윙이 있는 세션은 요약으로 가고 클립 목록이 보인다
- [ ] 저장소 읽기 실패·세션 없음이 화면에 사유로 남는다
- [ ] 촬영을 닫을 때 세션 id가 없으면(저장 실패·프레임 0장) 홈으로 간다
- [ ] 화면 상태가 **저장소 없이** 검증된다(가짜 `SessionRepository`)
- [ ] 요약·진단에 탭바가 없다
- [ ] 클린 빌드 경고 **0**

## 검증 방법

| 항목 | 방법 |
|---|---|
| 게이트 | `DEVELOPER_DIR=… CLEAN_BUILD=1 ./scripts/verify-ios.sh` |
| 문서 게이트 | `./scripts/verify-docs.sh` |
| 분기·로딩 | `ApplicationTests`(TCA `TestStore`) + 가짜 저장소 |
| 전이 | 촬영 종료 → 요약 열림, id 없으면 홈 |
| 테스트가 의미 있는가 | 뮤테이션 — 0개 판정을 뒤집기, 읽기 실패를 삼키기, id 없을 때도 요약을 열기 |

## 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 저장은 됐는데 읽기가 실패한다 | 사용자가 찍은 것을 못 본다 | 사유를 화면에 남긴다. 조용히 빈 화면을 띄우지 않는다 |
| 요약이 1-D 전까지 빈약하다 | "이게 다인가" | 있는 것만 보여주고 없는 것은 **자리도 만들지 않는다** — 빈 카드가 더 나쁘다 |
| 0개가 자주 나온다(#103) | 진단 화면만 계속 본다 | 그게 의도다. 원인을 짚는 것이 이 화면의 일이다 |
