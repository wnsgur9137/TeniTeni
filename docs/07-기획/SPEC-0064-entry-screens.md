# SPEC-0064. 진입 화면

> 이슈 [#64](https://github.com/wnsgur9137/TeniTeni/issues/64) · 마일스톤 `1-A′ 진입 화면`

## 배경

[#61](https://github.com/wnsgur9137/TeniTeni/issues/61)이 앱 셸을 만들었지만 **분기의 양쪽이 비어 있습니다.**

```swift
if store.hasCompletedOnboarding {
    tabs                    // 촬영 탭만 진짜
} else {
    TabPlaceholderView(...) // "온보딩은 1-A′에서 만듭니다"
}
```

**1-B가 이것 없이 시작되지 않습니다.** [비전 파이프라인 3.3](../02-설계/VISION-PIPELINE.md)이 `dominantHand`를 스윙 검출의 주 신호로 쓰는데, 값을 담을 그릇(`Handedness`·`UserPreferences`·저장소)은 #61이 만들었고 **물어보는 화면이 없습니다.**

화면 구성은 [IA-FLOW 10.2·10.4·10.7](../06-디자인/IA-FLOW.md)이, 토큰은 [11장](../06-디자인/DESIGN-SYSTEM.md)이, 계층 규칙은 [D-03](../05-결정/stack/D-03-architecture-pattern.md)이 정했습니다. **재론하지 않습니다.**

**목업 17종이 이미 있습니다** ([#48](https://github.com/wnsgur9137/TeniTeni/issues/48)). 새로 그리지 않고 구현합니다.

## 범위

### 만들 것

- `OnboardingFeature` — 소개 → 주 사용 손
- `HomeFeature` — 촬영 상황 5종 + 시합의 관찰 대상
- `SettingsFeature`
- `AppFeature`가 셋을 조합
- `TestStore` 기반 Reducer 테스트

### 만들지 않을 것

- **촬영 상황이 실제로 룰을 바꾸는 것** — 값을 고르고 저장할 뿐입니다. 룰 무효화는 **1-D**
- **관찰 대상이 파이프라인을 바꾸는 것** — **1-F**
- **코트 프리셋 관리** — 1-F. 설정에 항목만 두고 비활성
- **보관함·진척도 내용** — 1-E·2-E
- **예외 화면** — 권한 거부만. 나머지는 1-B·1-E

## 구현 선택지

### 1. Feature를 어떻게 나누는가

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `AppFeature` 하나에 전부 | 지금 구조 그대로 | 화면 넷의 상태가 한 `State`에 섞인다. 1-B가 더 붙으면 못 읽는다 |
| **B. 화면별 Feature + `AppFeature`가 조합** | [9.6](../04-계획/WORK-PLAN.md)의 "`Presentation` = 화면 단위 TCA Feature" 그대로 | 파일이 는다 |

**채택: B.** [D-03](../05-결정/stack/D-03-architecture-pattern.md)이 "`Presentation` 내 Feature 간 직접 의존 금지, `Application` 코디네이터 경유"를 정했으므로 **조합은 `AppFeature`가 합니다.**

### 2. 온보딩을 몇 단계로 두는가

`OnboardingHand` 목업의 스텝 인디케이터가 **3칸**인데 **세 번째 화면이 없습니다.** 제가 목업을 그릴 때 권한 화면을 가정했다가 만들지 않았습니다.

| 선택지 | 내용 |
|---|---|
| A. 권한 화면을 추가해 3칸 유지 | 왜 필요한지 설명한 뒤 물어 거부율을 낮춘다. 화면이 하나 는다 |
| **B. 2칸으로 줄이고 권한은 시스템 다이얼로그** | `Main`이 이미 "카메라와 마이크 권한이 필요합니다"를 적는다. **설명은 거기서 끝났다** |

**채택: B.** `Main`에서 이미 설명했는데 같은 말을 한 화면 더 하면 **온보딩만 길어집니다.** 목업의 인디케이터를 2칸으로 고칩니다.

> 마이크는 거부해도 **무음 녹화로 계속**합니다 ([IA-FLOW 10.6](../06-디자인/IA-FLOW.md)). 카메라 거부만 차단입니다.

### 3. 지난 선택을 어디에 두는가

홈이 "지난 선택을 미리 골라둔다"고 정해져 있습니다 ([IA-FLOW 10.4](../06-디자인/IA-FLOW.md)).

| 선택지 | 내용 |
|---|---|
| A. 세션 메타에서 마지막 것을 읽는다 | 세션 엔티티가 **1-B**에 생긴다. 지금 없다 |
| **B. `UserPreferences`에 `lastSituation`을 둔다** | 이미 있는 그릇이다. 1-B에서 세션 메타가 생기면 그때 옮길지 판단한다 |

**채택: B.** 없는 것을 기다리지 않습니다.

## 완료 기준

- [ ] 첫 실행이 **소개 → 주 사용 손 → 홈** 순으로 흐른다
- [ ] **주 사용 손 없이 촬영에 들어갈 수 없다**
- [ ] 주 사용 손이 저장되고 **재실행 시 온보딩을 건너뛴다**
- [ ] 홈에서 촬영 상황 5종을 고를 수 있고 **지난 선택이 미리 골라져 있다**
- [ ] **시합에서만** 관찰 대상 선택이 나타난다
- [ ] 각 상황 카드에 **배치 안내**가 붙는다
- [ ] 설정에서 주 사용 손을 바꿀 수 있다
- [ ] **세로 화면이 세로로 뜬다** (#61이 방향을 풀었다)
- [ ] `TestStore`로 온보딩 완료·상황 선택·손 변경이 고정된다
- [ ] `scripts/verify-ios.sh` 통과, 경고 0

## 검증 방법

| 항목 | 방법 |
|---|---|
| 게이트 | `scripts/verify-ios.sh` (`CLEAN_BUILD=1`로 한 번 더) |
| 상태 전이 | `TestStore` |
| 영속화 | 저장 후 **새 스토어**에서 읽히는지 |
| **변이 시험** | 주 사용 손 없이도 촬영에 들어가도록 바꿔 **테스트가 잡는지** |

**마지막이 핵심입니다.** "주 사용 손 없이 촬영에 못 들어간다"가 이 작업의 존재 이유이고, 그것을 테스트가 실제로 지키는지 확인해야 합니다.

| 촬영 상황을 저장만 하고 안 쓴다 | "고르는 의미가 없다"로 보임 | **UI에 "나중에 쓴다"고 적지 않는다.** 1-D에서 실제로 쓰기 시작한다 |
