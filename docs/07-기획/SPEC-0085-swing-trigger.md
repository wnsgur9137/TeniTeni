# SPEC-0085. 스윙 트리거 룰 엔진

> 이슈 [#85](https://github.com/wnsgur9137/TeniTeni/issues/85) · 마일스톤 `1-B 스윙 검출`

## 배경

1-B의 본체는 **포즈 시계열에서 스윙 구간을 잡아내는 것**인데 코드에 그 로직이 없습니다. 닫힌 1-B 이슈들은 기반만 다뤘습니다 — 링 버퍼와 영속화([#70](https://github.com/wnsgur9137/TeniTeni/issues/70)), 모듈 개명([#74](https://github.com/wnsgur9137/TeniTeni/issues/74)), 권한([#67](https://github.com/wnsgur9137/TeniTeni/issues/67)), 촬영 진입([#78](https://github.com/wnsgur9137/TeniTeni/issues/78)), UI 테스트([#83](https://github.com/wnsgur9137/TeniTeni/issues/83)).

트리거 공식은 [비전 파이프라인 3.3](../02-설계/VISION-PIPELINE.md)이 이미 확정했습니다 — 각속도 임계 · 몸통 기준선 교차 · 최소 지속시간 · 히스테리시스 · 0.8초 재트리거 차단. **그것을 재론하지 않고 구현 형태만 정합니다.**

### 왜 지금인가

트리거는 **포즈 시계열을 입력으로 받는 순수 계산**입니다. 카메라도 GPU도 필요 없고 합성 시계열로 전부 고정됩니다 — [SPEC-0040](SPEC-0040-render-transform.md)의 `RenderTransform`과 같은 성격입니다.

지금 열려 있는 이슈는 전부 사람이나 실기기에 달려 있습니다 — [#82](https://github.com/wnsgur9137/TeniTeni/issues/82)(실기기), [#54](https://github.com/wnsgur9137/TeniTeni/issues/54)(코치 자문), [#4](https://github.com/wnsgur9137/TeniTeni/issues/4)(🚧Blocked). 트리거를 먼저 세워두면 포즈 검출([작업 순서 9.3](../04-계획/WORK-PLAN.md)의 0-D #4)이 실기기를 얻는 날 붙이기만 하면 됩니다.

## 범위

### 만들 것

- `TeniVision/Sources/Swing/PoseFrame.swift` — 포즈 한 프레임. 관절 6개(양 어깨·양 엉덩이·양 손목) + 신뢰도 + 타임스탬프
- `TeniVision/Sources/Swing/SwingTriggerProfile.swift` — 임계·지속시간·간격을 담는 값 타입. 기본값과 벽치기 프로파일
- `TeniVision/Sources/Swing/SwingTrigger.swift` — 프레임을 하나씩 먹고 후보 구간을 내놓는 상태 기계
- `TeniVision/Tests/SwingTriggerTests.swift` — 합성 시계열 생성기 + 트리거 거동 테스트

### 만들지 않을 것

| 항목 | 사유 |
|---|---|
| 포즈 검출 (`DetectHumanBodyPoseRequest`) | 0-D #4. 카메라 프레임이 있어야 검증된다 |
| Vision 관측 → `PoseFrame` 어댑터 | 같은 이유. 포즈 검출과 한 몸이다 |
| One Euro Filter | [스켈레톤 오버레이 4.6](../02-설계/SKELETON-OVERLAY.md)이 포즈 쪽에 뒀다. 트리거는 **평활화된 입력을 가정**한다 |
| 어깨 회전 보조 신호 | 주 신호가 선 뒤에 붙인다. 별도 이슈 |
| 볼머신 주기 사전정보 | 같음. 별도 이슈 |
| 분류기 2차 검증 | 1-D. 모델이 없다 |
| 클립 저장·화면 | 트리거가 구간을 내놓은 다음의 일 |

## 구현 선택지

### 1. 입력을 Vision 타입으로 받을 것인가

| 선택지 | 장점 | 단점 |
|---|---|---|
| `HumanBodyPoseObservation`을 직접 받는다 | 변환이 없다 | **테스트를 쓸 수 없다** — 관측을 합성할 공개 생성자가 없다 |
| 자체 `PoseFrame`을 받는다 | 합성 시계열로 거동을 전부 고정한다. `TeniVision`이 Vision에 묶이지 않는다 | 어댑터가 하나 늘어난다 (0-D #4가 만든다) |

**채택**: 자체 `PoseFrame`. 이 작업이 성립하는 유일한 이유가 "실기기 없이 검증된다"인데, Vision 타입을 받으면 그것이 사라집니다.

### 2. 주 신호를 무엇으로 재는가

[비전 파이프라인 3.3](../02-설계/VISION-PIPELINE.md)은 "손목 각속도"라고 적었습니다. 좌표는 정규화 좌표이므로 **무엇에 대한 각인지**를 정해야 합니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| 손목의 선속도 (정규화/s) | 가장 단순 | **거리에 종속** — 8m에서 찍으면 같은 스윙이 절반 값이 된다 |
| 어깨너비로 나눈 선속도 | 거리 불변 | 설계가 쓴 말과 다르다 |
| **어깨 중점 기준 손목 벡터의 각속도 (rad/s)** | 거리 불변. 설계 용어와 일치 | 손목이 몸 중심에 가까우면 각이 폭주한다 |

**채택**: 각속도. 폭주는 **반경 하한**으로 막습니다 — 손목-어깨중점 거리가 어깨너비의 일정 비율 미만인 프레임은 신호로 치지 않습니다.

각도 단위는 라디안입니다 ([동시성 6.7](../02-설계/CONCURRENCY.md)).

### 3. 몸통 기준선 교차를 어떻게 정의하는가

어깨 중점과 엉덩이 중점을 잇는 축을 몸통선으로 두고, **손목이 그 축의 어느 쪽에 있는지의 부호**가 바뀌면 교차로 봅니다. 축은 사람이 기울어져도 따라가므로 화면 수직선보다 안정적입니다.

### 4. 상태를 어디에 두는가

| 선택지 | 장점 | 단점 |
|---|---|---|
| `actor SwingTrigger` | 호출처를 가리지 않는다 | **순서가 코드에 드러나지 않는다** — [동시성 6.1](../02-설계/CONCURRENCY.md)이 재진입을 이유로 금지 |
| `struct` + `mutating func` | 순서가 호출자에게 보인다. 테스트가 동기적이다 | 호출자가 격리를 책임진다 |

**채택**: `struct` + `mutating func`. 동시성 6.2가 `TeniVision`의 순수 계산을 `nonisolated`로 배치했고, 프레임 파이프라인은 이미 단일 `Task`가 순서대로 돌립니다.

### 5. 히스테리시스의 형태

| 선택지 | 장점 | 단점 |
|---|---|---|
| 단일 임계 + 쿨다운 | 파라미터가 하나 적다 | 임계 근처에서 떠는 신호가 켜짐/꺼짐을 반복한다 |
| **진입 임계 > 이탈 임계** | 떨림이 상태를 흔들지 못한다 | 값 두 개를 맞춰야 한다 |

**채택**: 2임계. 0.8초 재트리거 차단은 그와 별개로 둡니다 — 채터링과 "같은 스윙을 두 번 잡는 것"은 다른 문제입니다.

### 6. 신뢰도가 낮은 프레임

보간하지 않습니다. **신호로 치지 않고 상태를 유지**하되, 연속 결측이 일정 시간을 넘으면 진행 중이던 트리거를 버립니다. 사람이 프레임 밖으로 나간 경우를 스윙으로 만들지 않기 위해서입니다.

### 7. 교차 판정과 각속도를 분리한다

> 구현 중 자체 리뷰에서 드러나 추가한 항목입니다.

반경 하한에 걸린 프레임은 **각속도를 못 내지만 위치는 압니다.** 둘을 한 덩어리로 버리면 교차를 놓칩니다 — 그라운드스트로크의 손목은 몸통선을 지나는 바로 그 순간 어깨 중점에 가장 가까워서, **반경 하한이 겨냥한 구간과 교차 구간이 겹칩니다.**

각속도는 끊고(이어 붙이면 없는 각속도가 생깁니다) 교차 판정은 이어갑니다.

같은 이유로 **부호가 0인 프레임을 건너뜁니다.** 손목이 몸통선 위에 정확히 놓이면 부호의 곱으로 판정하는 방식은 들어가는 곱과 나오는 곱이 모두 0이 되어 교차를 통째로 잃습니다. 정규화 좌표에서는 부동소수점 흡수로 **실제로 정확히 0이 됩니다** — `0.18 · cos(90°) ≈ 1.1e-17`은 `0.5`의 ulp 아래입니다.

### 8. 최소 지속시간은 신호가 있던 시간으로 센다

> 같은 리뷰에서 나온 항목입니다.

무장 시각부터의 **벽시계 시간**으로 재면 그 사이가 결측이어도 지속시간이 채워집니다 — 신호 없이 조건이 충족됩니다. 각속도를 실제로 평가한 프레임의 `dt`만 누적합니다.

### 9. 재발화를 무장 해제에 묶지 않는다

> 같은 리뷰에서 나온 항목입니다.

발화 후 에피소드를 닫아버리면, 각속도가 이탈 임계 아래로 떨어질 때까지 다시 울릴 수 없습니다. **벽치기처럼 팔이 멈추지 않는 동작에서는 그 일이 일어나지 않아** 두 번째 스윙이 간격과 무관하게 영구히 막힙니다. 교차만 소비하고 무장은 유지합니다 — 중복은 `refractoryPeriod`가 막습니다.

## 완료 기준

- [ ] `SwingTrigger`가 합성 스윙 시계열에서 후보 구간을 1개 낸다
- [ ] 후보 구간이 `[t-2s, t+2s]`다 (`t` = 교차가 일어난 프레임의 타임스탬프)
- [ ] 진입 임계 근처에서 떠는 신호가 후보를 2개 이상 만들지 않는다
- [ ] 0.8초 이내의 두 번째 피크가 후보를 만들지 않는다
- [ ] 벽치기 프로파일이 기본 프로파일로는 놓치는 낮은 피크를 잡는다
- [ ] 손목이 몸통선을 넘지 않는 큰 팔 움직임(공 줍기 모사)이 후보를 만들지 않는다
- [ ] 반경 하한 미만 프레임이 각속도 폭주로 후보를 만들지 않는다
- [ ] 신뢰도 결측이 이어지면 진행 중이던 트리거가 버려진다
- [ ] 결측이 최소 지속시간을 대신 채우지 않는다
- [ ] 교차 순간 손목이 몸 중심에 가까워도(반경 하한 미달) 잡는다
- [ ] 손목이 몸통선 위에 정확히 놓이는 프레임이 끼어도 교차를 본다
- [ ] 쉬지 않고 도는 동안에도 간격만 지나면 다시 잡는다
- [ ] 쓸 수 있는 프레임 사이가 비면 진행 중이던 트리거를 버린다
- [ ] 역행하는 타임스탬프가 상태를 흔들지 않는다
- [ ] 왼손잡이 경로가 실제로 동작한다
- [ ] `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer ./scripts/verify-ios.sh` 통과
- [ ] **새로 넣은 코드의 경고 0** — 게이트 전체의 경고 0이 아니다. `CaptureFlowUITests.swift`(#83)에 기존 동시성 경고 76건이 있고, 이 작업에서 그 파일을 건드리면 재컴파일되며 드러난다. 고치려면 `setUp`/`tearDown`의 액터 격리를 손봐야 해 범위가 다르다 — [#88](https://github.com/wnsgur9137/TeniTeni/issues/88)

## 검증 방법

| 항목 | 방법 |
|---|---|
| 게이트 | `scripts/verify-ios.sh` (`TeniVisionTests` 포함) |
| 거동 | 합성 포즈 시계열 — 스윙 1회 · 떨림 · 연속 2회 · 공 줍기 · 저신뢰도 |
| 테스트가 의미 있는지 | **뮤테이션 4건** — 이탈 임계를 진입 임계와 같게, 재트리거 간격을 0으로, 교차 조건 제거, 0 부호 건너뛰기 제거. 넷 다 테스트가 죽여야 한다 |
| 리뷰가 찾은 미검출 | 새 테스트 4건을 **고치기 전 구현**에 돌려 전부 실패하는지 확인한다 |
| 실제 임계값 | **검증 불가** — 0-B 촬영과 #54가 있어야 한다. 아래 "미수행" 참조 |

## 미수행으로 남길 것

- **실제 임계값 결정** — 0-B 촬영 영상과 [#54](https://github.com/wnsgur9137/TeniTeni/issues/54) 코치 자문이 필요합니다. 이번에 넣는 값은 잠정값입니다
- **실영상 검증** — 합성 시계열로만 확인합니다. 실제 포즈 출력으로 돌려본 적이 없습니다
- **포즈 검출과의 연결** — 0-D #4가 실기기를 얻은 뒤입니다
- **성능 측정** — 120fps 8.3ms 예산 안인지는 실기기에서 잽니다
- **UI 테스트의 동시성 경고 76건** — `CaptureFlowUITests.swift`의 액터 격리 문제입니다. `@MainActor`를 클래스에 붙이면 `setUp`/`tearDown`이 상위의 `nonisolated` 선언을 override해 `sending 'self' risks causing data races`로 막힙니다. 파일 구조를 바꿔야 하므로 [#88](https://github.com/wnsgur9137/TeniTeni/issues/88)로 넘깁니다
- **UI 테스트 런너가 비정상 종료한 원인** — 1회차 게이트에서 첫 UI 테스트의 런너가 죽었습니다. 크래시 리포트를 확보하지 못해 앱이 죽은 것인지 런너가 타임아웃한 것인지 **구분하지 못했습니다.** 앱을 지운 뒤에는 재현되지 않습니다 — [#88](https://github.com/wnsgur9137/TeniTeni/issues/88)
