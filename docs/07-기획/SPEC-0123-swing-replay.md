# SPEC-0123. 스윙 리플레이

> 이슈 [#123](https://github.com/wnsgur9137/TeniTeni/issues/123) · 후행 [#121](https://github.com/wnsgur9137/TeniTeni/issues/121)

## 배경

[IA-FLOW 10.2](../06-디자인/IA-FLOW.md)가 이렇게 적었습니다 — "**4번이 이 앱의 심장입니다. 나머지는 4번으로 가는 경로이거나 4번의 집계입니다.**" 그 4번이 스윙 리플레이입니다.

입구는 둘 다 섰습니다. 촬영 직후([#110](https://github.com/wnsgur9137/TeniTeni/issues/110))와 보관함([#116](https://github.com/wnsgur9137/TeniTeni/issues/116))이 모두 세션 요약으로 들어옵니다. **목적지가 비어 있습니다.** 요약의 클립 목록은 지금 누를 수 없는 목록입니다.

그리고 [#121](https://github.com/wnsgur9137/TeniTeni/issues/121)이 오버레이 레이어를 설계했는데 **올릴 화면이 없습니다.** 이 작업이 그 선행입니다.

## 범위

### 만들 것

- 스윙 단위 재생 — `AVPlayer` + `AVPlayerLayer`
- 배속 전환 — **0.125× / 0.25× / 0.5× / 1×**, 기본 0.25×
- 프레임 단위 이동 — 앞뒤 한 프레임씩
- 페이즈 스크러버 — 스윙 구간을 타임라인에 걸고 **임팩트로 점프**
- 세션의 스윙을 앞뒤로 넘기기 — **클립 경계를 넘어서**
- 클립 파일이 없을 때의 화면
- **영상을 탭하면 가로 전체화면** — 아래 선택지 8
- 오버레이가 올라갈 자리 — [#121](https://github.com/wnsgur9137/TeniTeni/issues/121)이 그 위에 그린다

### 만들지 않을 것

| 항목 | 왜 |
|---|---|
| **피드백 문구** | [IA-FLOW 10.8](../06-디자인/IA-FLOW.md)이 신뢰도로 지시형/제시형을 가르는데 그 임계값이 **코치 자문([#54](https://github.com/wnsgur9137/TeniTeni/issues/54)) 선행**이고, 1-D 룰 엔진도 없다. 빈 카드를 만들지 않는다 — [SPEC-0110](SPEC-0110-session-summary.md)이 같은 판단을 했다 |
| 오버레이 레이어 | [#121](https://github.com/wnsgur9137/TeniTeni/issues/121)이 한다. **자리만** 만든다 |
| 점수·유형 라벨 | 1-D 분류가 만든다. `Swing.kind`는 지금 항상 `nil`이다 |
| 5페이즈 구분 | **데이터에 없다** — 아래 "목업과 어긋나는 것" |
| 레퍼런스 고스트·좌우 비교 | Phase 2 ([스켈레톤 오버레이 4.7](../02-설계/SKELETON-OVERLAY.md)) |
| 주석·그리기 | [Onform](../08-레퍼런스/Onform.md)의 핵심이지만 우리 범위 밖 |
| 내보내기·공유 | 별 작업 |
| 매크로 스크러버 | 아래 선택지 4 |

## 레퍼런스에서 가져온 것

[Onform](../08-레퍼런스/Onform.md) 조사(2026-10-29)의 결론 셋입니다.

1. **스크러버 하나로는 안 된다.** Onform은 매크로와 프레임 스크러버 둘을 둡니다. 390pt에 10초를 걸면 1px가 약 26ms — 120fps에서 3프레임입니다. 우리는 **구간이 1~2초**라 그 문제가 작아지고, 대신 "구간 찾기"를 앞뒤 스윙 넘기기가 대신합니다
2. **배속 하한은 1/8×.** Onform이 2×~1/8×입니다. 이슈 본문은 0.1×로 적었는데 **0.125×로 바꿉니다** — 아래 선택지 2
3. **리플레이도 발열·배터리를 쓴다.** Onform 리뷰에서 반복되는 불만입니다. 우리는 촬영에만 [ADR-0005](../05-결정/adr/ADR-0005-thermal-auto-adjust.md) 대응이 있습니다 — 리플레이는 측정 전이므로 아래 리스크에 남깁니다

[Hudl Technique](../08-레퍼런스/HudlTechnique.md)의 페이즈 스크러버는 **볼 수 없었습니다.** 앱이 2021년에 종료됐습니다. 레퍼런스 허브가 그 앱을 "페이즈 스크러버"로 적어 둔 것이 무효가 되었고, 그 사실을 레퍼런스 문서에 적었습니다.

## 구현 선택지

### 1. 재생 단위 — 클립인가 스윙인가

| 선택지 | 장점 | 단점 |
|---|---|---|
| **스윙** | 이슈가 요구한 "클립 경계를 넘어 앞뒤로"가 자연스럽다. 요약의 "스윙 34개"와 번호가 맞는다 | 클립이 바뀔 때 플레이어 아이템을 갈아야 한다 |
| 클립 | 아이템 교체가 없다 | **"12번째 스윙"을 말할 수 없다.** 사용자가 세는 단위는 스윙이다 |

**채택: 스윙.** 세션의 모든 클립을 펼쳐 `(clip, swing)` 순서열 하나로 만듭니다. 같은 클립 안에서 다음 스윙으로 가면 **`seek`만** 하고, 클립이 바뀔 때만 `replaceCurrentItem(with:)`을 부릅니다.

정렬은 `clips` 순서 안에서 `startSeconds` 순입니다. 클립 순서는 이미 `recordedAt`으로 정해져 저장됩니다.

### 2. 배속 하한 — 0.1×인가 0.125×인가

이슈 본문은 `0.1× / 0.25× / 0.5× / 1×`로 적었습니다. **0.125×로 바꿉니다.**

- 1/8이므로 120fps 클립이 정확히 **15fps**로 보입니다. 0.1×는 12fps이고 2의 거듭제곱이 아니라 프레임 표시 간격이 고르지 않습니다
- [Onform](../08-레퍼런스/Onform.md)의 하한과 같습니다 — 사용자가 다른 앱에서 익힌 감각과 어긋나지 않습니다
- 0.25×의 **정확히 절반**이라 "한 단계 더 느리게"가 눈에 맞습니다

`AVPlayer.rate`는 임의의 양수를 받지만 실제 지원은 `AVPlayerItem.canPlaySlowForward`에 달려 있습니다. **`false`면 배속 칩을 비활성화하고 1×로 떨어집니다** — 조용히 1×로 재생하면 사용자가 "느리게 안 된다"를 영상으로 오해합니다.

### 3. 구간 경계 — 끝에서 멈추는가 반복하는가

| 선택지 | 장점 | 단점 |
|---|---|---|
| **구간 반복** | 스윙 하나가 1~2초다. 멈추면 매번 다시 눌러야 한다 | 끝났다는 신호가 약하다 |
| 끝에서 멈춤 | 끝을 안다 | 0.25×로 봐도 8초, 그때마다 재생 버튼 |
| 다음 스윙으로 자동 진행 | 손을 안 쓴다 | **원하지 않는 이동이다.** 한 스윙을 반복해 보는 것이 이 화면의 용도다 |

**채택: 구간 반복.**

경계 검출은 `addBoundaryTimeObserver(forTimes:)`로 합니다. `forwardPlaybackEndTime`을 거기 두는 방법도 있지만 **Apple 문서가 그 시점에 `didPlayToEndTime`이 오는지 적지 않았습니다** — 적혀 있지 않은 동작에 기대지 않습니다.

반복할 때 되감기는 `seek(to:toleranceBefore:.zero, toleranceAfter:.zero)`입니다. 관용값을 주면 매 바퀴 시작점이 흔들립니다.

### 4. 스크러버 — 무엇을 재는가

**스윙 구간만 잽니다.** 클립 전체가 아닙니다.

```
 start                impact                    end
   ├────────────────────┼──────────────────────────┤
   0.0s                0.6s                     1.8s
```

[Onform](../08-레퍼런스/Onform.md)의 매크로 스크러버에 대응하는 것은 우리에게 **앞뒤 스윙 넘기기**입니다. 긴 타임라인을 훑는 대신 검출된 스윙 사이를 건너뜁니다 — 구간 찾기는 검출이 이미 했습니다.

임팩트는 **마커와 탭 타깃 둘 다**입니다. 눌러서 그 프레임으로 점프합니다. 기본 재생 위치도 임팩트가 아니라 **구간 시작**입니다 — [IA-FLOW 10.8](../06-디자인/IA-FLOW.md)은 "기본 재생 위치도 임팩트여야 한다"고 적었지만 그 근거는 "대부분의 지표가 그 프레임에서 계산되기 때문"이고, **지표가 아직 없습니다.** 지표를 보여줄 때 임팩트에서 시작하는 것이 맞고, 영상만 보는 지금은 스윙을 처음부터 보는 것이 맞습니다. 그 사실을 IA-FLOW에 적습니다.

### 5. 프레임 이동

`AVPlayerItem.step(byCount:)`을 ±1로 부릅니다. `canStepForward`·`canStepBackward`를 먼저 봅니다.

재생 중에 누르면 **먼저 일시정지합니다.** 재생과 스텝이 섞이면 어디로 갔는지 알 수 없습니다.

스텝의 크기는 "활성 트랙이 정하는 것"이라 문서가 적고 있습니다 — 우리 클립은 비디오 트랙 하나이므로 한 프레임입니다. 오디오는 녹음하지 않습니다([SPEC-0091](SPEC-0091-swing-clip-recording.md)).

### 6. 클립 파일이 없을 때

레코드는 SwiftData에 있고 파일은 `URL.documentsDirectory` 아래에 있습니다. 둘은 **따로 사라질 수 있습니다** — [#120](https://github.com/wnsgur9137/TeniTeni/issues/120)이 목록 쪽에서 같은 문제를 다룹니다.

| 선택지 | 단점 |
|---|---|
| **열기 전에 확인하고 상태로 표현** | 확인 비용(파일 1회 stat) |
| 열고 나서 `AVPlayerItem.status == .failed`로 처리 | 플레이어 오류 문구는 사용자에게 설명이 안 된다 |

**채택: 열기 전 확인.** 파일 경로 해석을 `ClipLocator`로 떼어냅니다 — `fileName`을 받아 **존재하는 URL이나 `nil`**을 돌려주는 값 타입입니다. [#120](https://github.com/wnsgur9137/TeniTeni/issues/120)이 목록에서 같은 타입을 씁니다.

없는 스윙은 **넘기기에서 건너뛰지 않습니다.** 건너뛰면 "34개 중 12번째"의 분모가 달라져 사용자가 세던 수와 어긋납니다. 그 자리에 들어가면 "이 클립의 영상 파일이 없습니다"가 나옵니다.

### 7. `AVPlayer`를 TCA 어디에 두는가

`AVPlayer`는 참조 타입이고 `Equatable`이 아니므로 **`State`에 들어갈 수 없습니다.**

촬영이 쓰는 구조를 그대로 씁니다 — `CaptureScreen`이 `CameraController`를 `@State`로 소유하고 `CaptureFeature`는 순수 상태만 가집니다.

| 조각 | 책임 |
|---|---|
| `ReplayFeature` | 플레이리스트·현재 인덱스·배속·일시정지·단계. **AVFoundation을 모른다** |
| `ReplayPlayer` | `@MainActor @Observable`. `AVPlayer`·`AVPlayerLayer`·관측자 소유 |
| `ReplayScreen` | 둘을 잇는다. `ReplayPlayer`를 `@State`로 소유 |
| `ReplayView` | 그린다 |

이 분리가 **테스트를 가능하게 하는 지점**입니다. 배속·인덱스·스크러버 위치는 전부 `ReplayFeature`와 값 타입 안에 있으므로 `TestStore`로 고정됩니다. 시뮬레이터에서 영상을 재생하지 않고도 검증됩니다.

### 8. 표시 방향 — 영상은 가로인데 화면은 세로다

**촬영이 landscape 고정**이므로 클립은 가로입니다. 그런데 [IA-FLOW 10.9](../06-디자인/IA-FLOW.md)는 "세로(390×844)는 일반 화면, 가로(844×390)는 촬영·중간 확인 화면"으로 정했고 기존 리플레이 목업 둘도 세로입니다.

390pt 폭에 16:9를 넣으면 영상 높이가 **219pt**입니다. [프레이밍 가이드](SPEC-0078-start-capture.md)가 선수를 프레임 높이의 35~45%에 두므로 화면 위의 사람은 **약 88pt**입니다. [#121](https://github.com/wnsgur9137/TeniTeni/issues/121)이 올릴 관절 19개가 거기서 뭉칩니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| **세로 기본 + 탭하면 가로 전체화면** | 세로가 집이므로 10.8의 피드백 자리가 보존된다. 자세히 볼 때만 가로 | 화면 상태가 하나 늘어난다 |
| 가로 고정 | 영상이 가장 크다(사람 약 156pt). 낭비가 없다 | **10.8의 세로 레이아웃을 전부 다시 설계해야 한다** — 피드백 카드가 들어갈 자리가 없다 |
| 세로 레터박스만 | 문서를 고칠 일이 없다 | 사람이 88pt. 오버레이가 읽히는지 알 수 없다 |

**채택: 세로 기본 + 탭하면 가로 전체화면.** 영상을 탭하면 `OrientationLock.lock(to: .landscape)`로 가로 전체화면, 다시 탭하면 `release()`로 돌아옵니다. 그 타입이 이미 있습니다 — 촬영이 쓰는 `OrientationLock`입니다.

전체화면에서도 **같은 `AVPlayer`를 씁니다.** 아이템을 갈지 않으므로 재생 위치·배속이 유지됩니다. 바뀌는 것은 `AVPlayerLayer`의 프레임과 컨트롤 배치뿐입니다.

[IA-FLOW 10.9](../06-디자인/IA-FLOW.md)의 "세로는 일반 화면" 규약에 **리플레이가 예외**로 들어갑니다. 문서를 고칩니다.

## 목업과 어긋나는 것

`_canvas/ReplayDirective.dc.html`·`ReplaySuggestive.dc.html`는 **피드백이 있는 1-D 이후의 화면**입니다. 지금 만드는 것과 둘이 다릅니다.

| 목업이 그린 것 | 지금 | 왜 |
|---|---|---|
| 지시 카드 + 근거 수치 | **없음** | 룰 엔진·코치 자문 선행 |
| "다른 지적 2개" 접힘 | 없음 | 같음 |
| 스켈레톤 오버레이 | **자리만** | [#121](https://github.com/wnsgur9137/TeniTeni/issues/121) |
| 페이즈 **5구간** 레이블 (준비·테이크백·포워드·임팩트·팔로스루) | **3점**(start·impact·end) | 아래 |
| 유형 라벨 "포핸드" | 없음 | `Swing.kind`가 `nil` |
| 세로 영상처럼 그린 인물 | **가로 영상 레터박스** | 촬영이 landscape 고정이다 — 위 선택지 8 |

### 5페이즈를 그리지 않는 이유

`Swing`이 가진 것은 `startSeconds`·`impactSeconds`·`endSeconds` **세 점**입니다. 준비/테이크백/포워드/팔로스루의 경계는 어디에도 없습니다. 비율로 나누면 **그럴듯하지만 거짓인 눈금**이 생깁니다 — 사용자가 "테이크백이 짧다"를 그 눈금으로 읽으면 우리가 만든 비율을 읽는 것입니다.

그래서 v1은 **임팩트 전 / 임팩트 / 임팩트 후**만 말합니다. 5페이즈는 1-D가 경계를 만든 뒤에 올립니다.

새 아트보드 **셋**(`Replay` 세로 · `ReplayFullscreen` 가로 · `ReplayMissing` 파일 없음)을 추가하고, 기존 둘은 **1-D 목표 상태**로 남깁니다 — 지우지 않습니다.

## 데이터 모델

```
ReplayItem                      값 타입. 플레이리스트의 한 칸
  clipID         UUID
  fileName       String
  swing          Swing
  clipFPS        Int            ADR-0005로 클립마다 다를 수 있다
  index          Int            1부터. 사용자가 보는 번호
  total          Int

PlaybackSpeed   enum            .eighth(0.125) | .quarter(0.25) | .half(0.5) | .normal(1)

ReplayFeature.Phase
  .loading
  .ready([ReplayItem], current: Int)
  .unavailable(reason)          세션을 못 읽음 / 스윙이 0개
```

`clipFPS`를 칸마다 들고 있는 이유: 발열로 강등되면 클립마다 fps가 다릅니다([ADR-0005](../05-결정/adr/ADR-0005-thermal-auto-adjust.md)). 세션의 fps를 가정하면 "프레임 하나"의 길이가 틀립니다 — [SPEC-0121](SPEC-0121-replay-overlay.md)이 사이드카에 `frameRate`를 적는 것과 같은 이유입니다.

### 세션을 다시 읽는다

요약이 들고 있는 `Session`을 넘기지 않고 **`sessionID`와 `swingID`를 넘겨 다시 읽습니다.** [SPEC-0110](SPEC-0110-session-summary.md) 선택지 1과 같은 판단입니다 — 넘겨받은 값을 그리면 저장 실패를 영원히 모릅니다.

### Feature 간 의존을 만들지 않는다

[D-03](../05-결정/stack/D-03-architecture-pattern.md)이 "`Presentation` 내 Feature 간 직접 의존 금지, `Application` 코디네이터 경유"를 정했습니다. 따라서 **세션 요약이 리플레이를 띄우지 않습니다.**

```
SessionSummaryFeature  ──delegate(.swingTapped(sessionID:, swingID:))──▶  AppFeature
                                                                            │
                                                                     @Presents replay
```

## 화면 상태

| 상태 | 화면 |
|---|---|
| 읽는 중 | 스피너 |
| 스윙 있음, 파일 있음 | 재생 화면 |
| 스윙 있음, **파일 없음** | "이 클립의 영상 파일이 없습니다" + 넘기기는 살아 있다 |

| `canPlaySlowForward == false` | 배속 칩 비활성, 1× 고정, 사유 표시 |
| **가로 전체화면** | 영상이 화면을 채우고 컨트롤이 아래에 겹친다. 같은 플레이어·같은 위치 |

## 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **120fps를 0.125×로 재생하면 끊긴다** | 이 화면의 존재 이유가 흔들린다 | `canPlaySlowForward`로 먼저 걸러낸다. 실기기에서 끊기면 **배속 하한을 0.25×로 올린다** — 그 판단은 보고 나서 한다 |
| 리플레이가 발열을 만든다 | 촬영 직후에 보는 화면이라 이미 뜨겁다 | 측정 전이다. [#129](https://github.com/wnsgur9137/TeniTeni/issues/129)에 항목을 넣는다 |
| 클립 교체가 눈에 띈다 | 넘기기가 덜컥거린다 | 같은 클립 안은 `seek`만. 교체는 클립이 바뀔 때만 |
| 피드백이 없어 화면이 비어 보인다 | "그래서 뭘 보라는 건가" | 빈 카드를 만들지 않는다는 것이 결정이다. [#121](https://github.com/wnsgur9137/TeniTeni/issues/121) 오버레이가 다음에 올라간다 |
