# SPEC-0006. 합성 영상 생성기

> 이슈 [#6](https://github.com/wnsgur9137/TeniTeni/issues/6) · 마일스톤 `0-C 검증`

## 배경

실기기와 코트가 막힌 상황에서 0-C 도구(#7 CLI, #8 라벨링, #9 스윙)를 검증할 유일한 수단입니다. **정답을 정확히 아는 입력**이 있어야 도구가 틀렸는지 입력이 나빴는지 가릅니다.

부수적으로 [촬영 프로토콜 5.3](../02-설계/CAPTURE-PROTOCOL.md)의 노출 가설을 실험으로 확인할 수 있습니다. 블러를 파라미터로 조절해 검출이 어디서 무너지는지 봅니다.

착수 전 조사는 [모션 블러와 공 추적](../08-레퍼런스/ml/MotionBlur.md)에 있습니다. 핵심만 옮기면:

- **블러 길이(px) = 공 속도(px/s) × 노출 시간.** BlurBall 논문 Eq. 8과 우리 프로토콜 5.3 표가 정확히 일치합니다
- 블러 합성은 **하위 프레임 누적**, 평균은 **선형 공간**에서
- 표본이 부족하면 연속 블러가 아니라 운동 방향으로 **끊긴 고스팅**이 나옵니다

## 범위

### 만들 것

- macOS CLI 실행 파일 `teni`와 그 첫 서브커맨드 `synth`
- 포물선 궤적으로 공이 지나가는 `.mov` 생성
- 조절 가능한 파라미터: 궤적 · 거리 · 화각 · 노출 · fps · 해상도 · 배경 · 노이즈
- 정답 JSON 동시 출력 — 프레임별 공 중심, 임팩트 프레임, 블러 길이

### 만들지 않을 것

- **롤링 셔터** — iPhone은 롤링 셔터지만 글로벌 셔터로 합성합니다. 고속 수평 운동의 기울어짐이 재현되지 않습니다. 이 차이가 검출에 영향을 주는지는 실영상에서만 알 수 있습니다
- **사람·라켓·코트 렌더링** — 공과 배경만. 포즈 검출은 0-C 범위가 아닙니다
- **렌즈 왜곡 · 비네팅 · ISO 노이즈 모델** — 균일 가우시안 노이즈만 둡니다
- **`analyze` · `label` · `sweep` 서브커맨드** — 각각 [#7](https://github.com/wnsgur9137/TeniTeni/issues/7) · [#8](https://github.com/wnsgur9137/TeniTeni/issues/8) · [#9](https://github.com/wnsgur9137/TeniTeni/issues/9)
- **게이트 판정에 합성 영상 사용** — [프로토콜 5.5](../02-설계/CAPTURE-PROTOCOL.md)의 분모는 사람이 센 실제 타구입니다. 합성은 도구 검증까지입니다

## 구현 선택지

### 1. 0-C 도구 4개를 어떻게 배치할 것인가

저장소 구조([REPOSITORY.md](../03-기술스택/REPOSITORY.md))에 CLI 도구 자리가 정의돼 있지 않습니다. #6에서 정해야 #7~#9가 따라갑니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 단일 실행 파일 `teni` + 서브커맨드** | JSON 포맷·입출력 코드가 한 곳. Tuist 타깃 1개, 게이트 단순 | 서브커맨드 하나를 고쳐도 전체가 재빌드 |
| B. 도구마다 실행 파일 | 독립적 | 공용 코드를 또 나눠야 함. 타깃 4개, 게이트 4배 |
| C. 스크립트(Python) | 빠른 작성 | **`TeniVision`을 못 씁니다** — `BallGeometry`·`ClipMetadata`를 재구현하게 되고 계산식이 두 벌이 됩니다 |

**채택: A.** C는 [SPEC-0005](SPEC-0005-tenivision-module.md)에서 계산식을 한 곳으로 모은 작업을 되돌립니다.

위치는 `ios/Projects/TeniTool/`입니다. `TeniVision`과 같은 Tuist 워크스페이스여야 `.project` 의존으로 바로 참조됩니다.

> `ios/` 아래에 macOS CLI가 있는 것은 어색합니다. 디렉터리 이름을 `apps/`로 바꾸는 것이 맞지만 이번 범위가 아닙니다 — 별도 이슈로 남깁니다.

### 2. 인자 파싱

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. swift-argument-parser** | 서브커맨드·`--help`·타입 검증 자동. Apple 공식 | 외부 의존성 1개 |
| B. 직접 파싱 | 의존성 0 | 파라미터가 10개 넘고 서브커맨드가 4개. 검증 코드를 직접 씀 |

**채택: A.** 이 저장소가 "의존성 0"을 반복해 택한 것은 [D-06](../05-결정/stack/D-06-pose-engine.md)·[D-12](../05-결정/stack/D-12-dependency-injection.md)처럼 **앱 바이너리**에 관한 판단입니다. `teni`는 개발 도구이므로 앱 크기·ANE·기동 시간과 무관합니다. 같은 원칙을 적용할 이유가 없습니다.

### 3. 렌더링

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. Core Graphics + AVAssetWriter** | 의존성 없음. 원·사각형이면 충분 | 하위 프레임 N장을 CPU로 그림 — 느림 |
| B. Metal | 빠름 | 오프라인 도구에 GPU 파이프라인은 과함 |

**채택: A.** 1/60s 최악 조건에서 하위 프레임 128장이지만, 그리는 것은 원 하나와 배경입니다. 속도가 문제가 되면 그때 B로 갑니다.

### 4. 블러 하위 표본 수

**채택: `N = max(8, ceil(블러 길이 px))`.** 하위 프레임 간 공 이동이 1 px 이하가 되어야 계단이 보이지 않습니다. 정확한 필요 표본 수를 못 박은 문헌은 찾지 못해 이 규칙을 씁니다 ([레퍼런스](../08-레퍼런스/ml/MotionBlur.md) 참고). `--blur-samples`로 덮어쓸 수 있게 둡니다.

## 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **합성 영상이 쉬워서 검출이 잘 되고, 실영상에서 무너진다** | 게이트를 낙관적으로 오판 | 게이트 판정에 합성을 쓰지 않는다고 범위에 못 박음. 배경 복잡도·노이즈를 파라미터로 두어 난이도를 올릴 수 있게 함 |
| 롤링 셔터 미구현이 실제 차이를 가림 | #7 결과가 실영상과 어긋남 | 기획서에 명시. 0-B 실영상 확보 시 첫 대조 항목 |
| CPU 렌더가 느려 실험 회전이 느려짐 | #9 파라미터 스윕 지연 | 해상도·길이를 줄여 반복하고, 최종만 1080p. 그래도 느리면 Metal |
| 외부 의존성 도입이 Tuist 설정을 복잡하게 함 | 빌드 실패 | `teni` 타깃에만 붙임. `TeniVision`과 앱은 의존성 0 유지 |
