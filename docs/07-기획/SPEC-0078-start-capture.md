# SPEC-0078. 촬영 시작 흐름

> 이슈 [#78](https://github.com/wnsgur9137/TeniTeni/issues/78) · 마일스톤 `1-B 스윙 검출`

## 배경

**촬영 화면이 앱에서 열리지 않습니다.** `AppFeature`의 `home(.delegate(.start))`가 `.none`이고, 촬영 탭 루트는 홈입니다. `CaptureView`·`CameraController`는 0-A에서 구현됐지만 도달할 경로가 없습니다.

[#67](https://github.com/wnsgur9137/TeniTeni/issues/67)에서 권한 거부 흐름을 고치다 드러났습니다. 권한 다이얼로그도, 무음 녹화도, 녹화 자체도 **사람이 확인할 방법이 현재 없습니다.** 0-A의 촬영 코드와 1-A′의 진입 화면 사이가 끊어져 있습니다.

또 하나. [IA-FLOW 10.3](../06-디자인/IA-FLOW.md)의 촬영 전 단계는 홈과 촬영 중 사이에 **프레이밍 가이드**를 두는데, 코드에도 목업에도 없습니다. 내용은 [촬영 프로토콜 5.6](../02-설계/CAPTURE-PROTOCOL.md)이 이미 정해 뒀습니다.

레퍼런스 [SwingVision](../08-레퍼런스/SwingVision.md)(조사 2026-09-11, 재사용)의 반복되는 불만이 바로 이 지점입니다 — **"카메라가 제대로 잡혔는지 확인할 수 없다."** 그들은 보조 기기로 풀었고, 우리는 촬영 전 한 화면으로 확인하게 합니다.

계층 규칙은 [D-03](../05-결정/stack/D-03-architecture-pattern.md)이, 라인 판정의 배치는 [ADR-0004](../05-결정/adr/ADR-0004-line-call-mode.md)가 이미 정했습니다. **재론하지 않습니다.**

## 범위

### 만들 것

- **홈 '시작' → 촬영 제시.** `AppFeature`가 `@Presents`로 촬영을 띄우고, 고른 `CaptureSituation`·`ObservationTarget`을 넘긴다
- **`CaptureFeature`** — 단계 둘(`framing` → `capturing`)과 종료 위임. 촬영 상황·관찰 대상을 들고 있다
- **프레이밍 가이드 화면** — 카메라 프리뷰 위에 구도 가이드와 배치 안내. 관찰 대상에 따라 안내가 다르다 ([촬영 프로토콜 5.6](../02-설계/CAPTURE-PROTOCOL.md)의 표)
  - 내 스윙: 인체 실루엣 밴드 — 선수가 프레임 높이의 35~45%
  - 라인 판정: 라인 밴드 — 판정할 라인이 화면을 가로지르게
- **종료 → 홈 복귀.** 촬영 화면에 닫기를 둔다
- **가로 고정을 실제로 적용** — 지금 `CaptureView.supportedOrientations`는 아무도 읽지 않는 죽은 선언이다
- **목업 아트보드 `FramingGuide.dc.html`**(844×390) 신규 + `canvas.json` 갱신
- **테스트** — 단계 전이, 관찰 대상별 안내, 종료 복귀

### 만들지 않을 것

- **코트 프리셋**(4점 탭 → 격자 검증) — 라인 판정 전용 단계다. 목업만 있고 화면이 없다. 별도 이슈
- **수평 가이드**(가속도계 ±3°), **흔들림 감지**(`CMMotionManager`), **조명 경고**(ISO 상한) — 센서값과 실측([#4](https://github.com/wnsgur9137/TeniTeni/issues/4))이 필요해 시뮬레이터에서 판정할 수 없다. 별도 이슈
- **세션 요약·이어서 촬영** — 종료하면 홈으로 돌아온다. 요약 화면은 1-E
- **녹화물 저장·세션 메타 기록** — 상황·관찰 대상을 세션에 기록하는 것은 저장 작업의 범위다
- **스윙 검출·오버레이** — 1-B 본체
- **촬영 상황이 룰을 바꾸는 것** — 1-D ([SPEC-0064](SPEC-0064-entry-screens.md)와 같은 선)

## 구현 선택지

| 지점 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 제시 방법 | **A. `fullScreenCover`** | 탭바가 가려진다. 방향 전환이 한 화면에서 끝난다 | 탭 전환으로 빠져나갈 수 없다(의도) |
| | B. 탭 콘텐츠 교체 | 구조가 단순 | 촬영 중 탭바가 남아 6m에서 오조작 |
| 상태 소유 | **A. `CaptureFeature` 신설** | 단계 전이가 테스트된다. 조합은 `Application`이 한다(D-03) | 타입이 하나 늘어난다 |
| | B. `CaptureView`가 자체 상태로 | 코드가 짧다 | 단계 전이를 테스트할 수 없다 |
| 방향 잠금 | **A. 마스크 홀더 + `AppDelegate`** | 제시된 화면에도 확실히 걸린다 | 진입점에 어댑터가 하나 붙는다 |
| | B. `requestGeometryUpdate`만 | 코드가 가장 짧다 | 사용자가 되돌릴 수 있다. 촬영 중 세로가 된다 |
| | C. `UIHostingController` 하위 클래스 | 화면 코드에 선언이 남는다 | 제시된 VC의 마스크는 **컨테이너가 답한다** — 자식 선언이 먹지 않는다 |
| 가이드 위치 | **A. 같은 Feature의 단계** | 카메라 세션을 한 번만 세운다 | 한 화면이 두 모습을 갖는다 |
| | B. 독립 화면 | 화면 하나당 책임 하나 | 세션을 두 번 세우거나 넘겨야 한다 |

**채택: 전부 A.**

방향 잠금은 [SPEC-0061](SPEC-0061-module-shell.md)이 "화면이 자기 방향을 안다"(선택지 3-A)로 정한 것을 지킵니다. 잠금을 **요청하는 쪽은 촬영 화면**이고, 마스크를 답하는 창구만 진입점에 둡니다. 홀더는 `Presentation`에 두고 `Application`이 재노출해, 앱 타깃이 `Application`만 아는 의존 방향([작업 순서 9.6](../04-계획/WORK-PLAN.md))을 깨지 않습니다.

## 완료 기준

- [ ] 홈에서 '시작'을 누르면 프레이밍 가이드가 뜬다 — 시뮬레이터 확인
- [ ] 프레이밍 가이드의 배치 안내·구도 가이드가 **관찰 대상에 따라 다르다** — 테스트
- [ ] '촬영 시작'을 누르면 촬영 화면으로 바뀐다 — 테스트(`phase == .capturing`)
- [ ] 촬영 화면에서 닫으면 홈으로 돌아온다 — 테스트(`capture == nil`)
- [ ] 촬영 화면은 가로로 뜨고, 돌아오면 홈이 세로로 돌아온다 — 시뮬레이터 회전
- [ ] `scripts/verify-ios.sh` 통과, 경고 0
- [ ] **변이 시험** — 관찰 대상 분기를 지우면 테스트가 깨진다

## 검증 방법

| 항목 | 방법 |
|---|---|
| 게이트 | `scripts/verify-ios.sh` (`📱UI` — [규약 12.7](../09-프로세스/PIPELINE.md)) |
| 화면 전환 | 시뮬레이터에서 홈 → 가이드 → 촬영 → 홈. 접근성 트리로 확인 |
| 방향 | 시뮬레이터 회전. 촬영은 가로 유지, 홈은 세로 복귀 |
| 단계 전이 | `AppFeatureTests` — `Presentation`이 보이는 유일한 iOS 테스트 타깃 |
| 카메라 프리뷰·녹화 | **실기기.** 시뮬레이터는 카메라가 없어 `.failed`로 빠진다 |
