# SPEC-0070. 1-B 기반 — 엔티티·영속화·링 버퍼

> 이슈 [#70](https://github.com/wnsgur9137/TeniTeni/issues/70) · 마일스톤 `1-B 스윙 검출`

## 배경

[#68](https://github.com/wnsgur9137/TeniTeni/issues/68)에서 영속화를 1-B로 옮겼습니다 — **저장할 곳 없이 클립을 저장할 수 없습니다.**

1-B의 나머지(스윙 검출)는 **포즈 추정에 달려 있고 그것은 실기기가 필요합니다.** 기반 셋은 그와 무관하므로 먼저 만듭니다.

엔티티의 뜻은 [용어집](../01-제품/PRODUCT-OVERVIEW.md)이, 저장 대상은 [D-08](../05-결정/stack/D-08-local-db.md)이, 계층 규칙은 [9.6](../04-계획/WORK-PLAN.md)이 정했습니다. **재론하지 않습니다.**

## 범위

### 만들 것

- `Domain` 엔티티 — `Session` · `Clip` · `Swing`
- Repository 프로토콜 (`Domain`) + SwiftData 구현 (`Data`)
- 링 버퍼 — 소급 저장용

### 만들지 않을 것

- **스윙 검출 로직** — 포즈가 필요하고 그것은 0-D #4(실기기)입니다
- **클립 파일 저장** — `AVAssetWriter`는 촬영이 돌아야 합니다
- **`Metrics`·`Feedback` 엔티티** — D-08이 목록에 올렸지만 **1-D가 무엇을 산출할지 정한 뒤**입니다. 지금 만들면 갈아엎습니다
- **마이그레이션 전략** — 스키마가 처음이라 이전할 것이 없습니다

## 구현 선택지

### 1. `Domain`이 SwiftData를 알게 할 것인가

[9.6](../04-계획/WORK-PLAN.md)이 **"`Domain`은 아무것도 import하지 않는다"** 를 규칙으로 정했습니다. 그런데 SwiftData의 `@Model`은 클래스에 붙는 매크로입니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `Domain` 엔티티에 `@Model` | 매핑 코드가 없다 | **`Domain`이 SwiftData를 import한다.** 9.6 위반 |
| **B. `Domain`은 순수 struct, `Data`에 `@Model` 별도** | 규칙을 지킨다. `Domain`이 테스트하기 쉽다 | 매핑 코드가 생긴다 |

**채택: B.** 규칙이 먼저입니다. 매핑은 단순하고, `Domain`이 순수하면 **저장 방식을 바꿀 때 엔티티가 안 흔들립니다** — D-08이 "GRDB 이전을 검토"할 여지를 남겼습니다.

### 2. 링 버퍼의 용량을 무엇으로 받을 것인가

소급 저장은 "스윙을 감지한 **뒤에** 그 전 2초를 꺼내는" 것입니다.

| 선택지 | 장단 |
|---|---|
| A. 프레임 수 | 단순하다. **fps가 바뀌면 시간이 달라진다** — 120fps의 240프레임은 2초, 60fps면 4초 |
| **B. 시간(초) + fps** | 의도가 그대로 드러난다. fps가 바뀌어도 2초는 2초다 |

**채택: B.** [프로토콜 5.2](../02-설계/CAPTURE-PROTOCOL.md)가 **fps를 사용자 선택**으로 뒀으므로 프레임 수로 받으면 조용히 어긋납니다.

### 3. 세션을 지우면 클립·스윙은 어떻게 되는가

| 선택지 | 내용 |
|---|---|
| **A. 함께 지운다 (cascade)** | 세션 없는 클립은 의미가 없다 |
| B. 남긴다 | 고아 데이터가 쌓인다 |

**채택: A.** 다만 **영상 파일은 이 작업의 범위가 아닙니다** — 메타데이터만 지웁니다. 파일 정리는 클립 저장이 생기는 시점에 함께 정합니다.

## 완료 기준

- [ ] `Session`·`Clip`·`Swing`이 `Domain`에 있고 **`dependencies: []`가 유지된다**
- [ ] Repository 프로토콜이 `Domain`, 구현이 `Data`
- [ ] **세션을 저장했다가 읽으면 같다** — 왕복 테스트
- [ ] 세션에 클립을, 클립에 스윙을 담을 수 있다
- [ ] **세션을 지우면 클립·스윙이 함께 지워진다**
- [ ] **링 버퍼가 용량을 넘으면 가장 오래된 것부터 버린다**
- [ ] **"마지막 N초"를 꺼낼 수 있다** — fps가 달라도 N초는 N초
- [ ] `scripts/verify-ios.sh` 통과, 경고 0

## 검증 방법

| 항목 | 방법 |
|---|---|
| 게이트 | `scripts/verify-ios.sh` (`CLEAN_BUILD=1`로 한 번 더) |
| 왕복 | 저장 → **새 컨테이너**에서 읽기. 같은 인스턴스에서 읽으면 캐시를 보는 것일 수 있다 |
| cascade | 세션 삭제 후 클립·스윙 수가 0인지 |
| 링 버퍼 | 빈 버퍼 · 가득 참 · 용량 초과 · fps 두 종류 |
| **변이 시험** | 링 버퍼가 오래된 것을 안 버리게, cascade를 끄게 바꿔 **테스트가 잡는지** |

**왕복 테스트를 새 컨테이너에서 하는 것이 중요합니다.** 같은 `ModelContext`에서 읽으면 메모리 캐시를 보게 되어 **실제로 디스크에 썼는지 확인되지 않습니다.**

## 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **엔티티를 미리 너무 정한다** | 1-D에서 갈아엎는다 | 지금 아는 것만 넣는다. `Metrics`는 1-D로 미룬다 |
| SwiftData가 `Domain`을 오염시킨다 | 9.6 위반 | 선택지 1의 B. 매니페스트에 의존성이 없는 것으로 확인한다 |
| 링 버퍼가 실제 프레임을 감당 못 함 | 1-B에서 드러남 | **제네릭으로 둔다.** 프레임이 아니라 아무 값이나 담게 하고, 실제 크기 문제는 촬영이 돌 때 잰다 |
| 왕복 테스트가 캐시를 본다 | 저장이 안 돼도 통과 | 새 컨테이너에서 읽는다. 검증 방법에 명시 |

## 미수행으로 남길 것

- **실기기 검증** — 실제 프레임을 링 버퍼에 넣어보는 것은 촬영이 돌아야 합니다
- **마이그레이션** — 스키마가 바뀌기 시작하면
- **`Metrics`·`Feedback`** — 1-D
- **영상 파일 정리** — 클립 저장이 생기는 시점
