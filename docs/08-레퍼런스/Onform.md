# Onform

> 영상 코칭 앱. 리플레이·주석 UX의 표준

## 2026-10-29 — 스크러버는 **두 겹**이다

이슈 [#123](https://github.com/wnsgur9137/TeniTeni/issues/123) 조사. 공개 지원 문서와 리뷰로 확인했습니다 — **앱을 써 본 것이 아닙니다.**

### 기능 범위 — 재생 조작

| 항목 | Onform |
|---|---|
| 배속 | **2× ~ 1/8×**(0.125×) |
| 프레임 이동 | 앞/뒤 버튼이 **한 프레임씩** |
| 스크러버 | **매크로**(영상 전체를 빠르게) + **프레임 스크러버**(미세) 두 개 |
| 다중 앵글 | 최대 4개를 동기 재생. 슬로우 모션·프레임 이동 중에도 유지 |
| 기타 | 스톱워치, 자, 스켈레톤 추적, 그리기 주석, 좌우 비교, 음성 피드백 |

**두 겹 스크러버가 이 조사의 핵심 발견입니다.** 2021년 소프트볼 코치 리뷰도 같은 것을 "빠르게 왕복하는 도구 하나 + 훨씬 미세하게 움직이는 휠 하나"로 기술했습니다. 하나의 스크러버로 전체 길이와 프레임 정밀도를 동시에 만족시킬 수 없다는 뜻입니다 — 390pt 폭에 10초를 걸면 1px가 약 26ms, 120fps에서 **3프레임**입니다.

### 사용자 불만

App Store 평점 3.7/5 (475건, 1점 109건). 스크러버 자체를 지적하는 리뷰는 찾지 못했습니다. 반복되는 것은 다른 곳입니다.

| 불만 | 우리에게 주는 것 |
|---|---|
| **배터리가 빨리 닳고 기기가 뜨거워진다** | 리플레이도 발열원이다. 우리는 촬영에만 [ADR-0005](../05-결정/adr/ADR-0005-thermal-auto-adjust.md) 대응이 있다 |
| **영상을 지워도 캐시가 남아 수 GB가 된다** | [#124](https://github.com/wnsgur9137/TeniTeni/issues/124)·[#126](https://github.com/wnsgur9137/TeniTeni/issues/126)이 같은 종류의 문제다 |
| 강제 클라우드 업로드, 저장 10개 제한 | 우리는 기기 안에서 완결한다([D-01](../05-결정/stack/D-01-deployment-target.md)) |
| 메뉴가 혼란스럽다 | 리플레이에 컨트롤을 쌓지 않는다 |

### 우리와의 차이

| | Onform | TeniTeni |
|---|---|---|
| 재생 단위 | **영상 하나** | **스윙 하나** — 구간이 이미 검출돼 있다 |
| 스크러버가 재는 것 | 영상 전체 길이 | 스윙 구간(1~2초)과 그 안의 임팩트 |
| 매크로 스크러버의 역할 | 긴 영상에서 구간 찾기 | **필요 없다.** 구간 찾기는 검출이 이미 했다 |
| 주석·그리기 | 핵심 기능 | 범위 밖 |

**Onform의 매크로 스크러버에 대응하는 것이 우리에게는 "앞뒤 스윙 넘기기"입니다.** 긴 타임라인을 훑는 대신 검출된 스윙 사이를 건너뜁니다. 두 겹 중 **미세한 쪽만** 남기는 설계입니다 — 근거는 구간이 이미 1~2초로 짧다는 것입니다.

### 한계

지원 문서·마케팅 페이지·리뷰로 얻었습니다. **배속 전환의 반응 속도, 프레임 이동의 체감, 스크러버의 손맛은 조사로 알 수 없습니다.** 그것은 우리 앱을 실기기에서 써 보고 판단합니다.
