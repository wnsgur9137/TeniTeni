# 모션 블러와 공 추적

> 노출 시간이 공 검출을 좌우하는 이유와, 그것을 합성 영상으로 재현하는 방법.

이슈 [#6 합성 영상 생성기](https://github.com/wnsgur9137/TeniTeni/issues/6) 착수 전 조사입니다.

## 1. 블러와 속도의 관계 — BlurBall (2026)

[BlurBall: Joint Ball and Motion Blur Estimation for Table Tennis Ball Tracking](https://arxiv.org/html/2509.18387)

탁구공 추적에서 블러 streak을 속도 추정에 **역이용**한 논문입니다. 블러를 제거할 대상이 아니라 정보로 봅니다.

### 핵심 관계식 (논문 Eq. 8)

```
Ṗx = l·cos(θ) / t_exp
Ṗy = l·sin(θ) / t_exp
```

`l` = 블러 반길이(px), `θ` = streak 각도, `t_exp` = 노출 시간.

정리하면 **블러 길이 = 속도(px/s) × 노출 시간**입니다. 단순하지만 우리 설계의 근거가 바로 이것입니다.

### 우리 문서 수치 검산

[촬영 프로토콜 5.3](../../02-설계/CAPTURE-PROTOCOL.md)의 번짐 표를 위 관계식으로 재계산했습니다. 조건: 시속 100 km, 거리 6 m, 화각 70°, 1920 px (공 지름 15.31 px, 6347 px/s).

| 노출 | 이동 | 번짐 (계산) | 문서 표기 | 공 지름 대비 |
|---|---|---|---|---|
| 1/60 s | 46.3 cm | 105.8 px | 107 px | 691 % |
| 1/250 s | 11.1 cm | 25.4 px | 26 px | 166 % |
| 1/500 s | 5.6 cm | 12.7 px | 13 px | 83 % |
| **1/1000 s** | **2.8 cm** | **6.35 px** | **6 px** | **41 %** |

**전부 일치합니다.** 반올림 차이뿐입니다. 1/1000s 고정 결정([D-06 이하 촬영 스펙](../../05-결정/DECISION-LOG.md) 및 프로토콜 5.3)의 물리적 근거가 독립 문헌으로 확인됐습니다.

### 그대로 가져올 수 없는 것

| 논문 결과 | 우리 상황 |
|---|---|
| 최대 73 px 블러에서도 검출 성공 | **전이되지 않습니다.** 논문 모델은 블러 데이터로 학습했고, `DetectTrajectoriesRequest`는 그렇지 않습니다 |
| `l ≤ 3 px`이면 블러 각도 추정이 노이즈에 묻힘 | 우리 1/1000s는 `l ≈ 3.2 px` — 경계입니다. **블러에서 속도를 얻으려면 1/1000s는 오히려 너무 짧습니다** |
| 합성 데이터 미사용 (실영상 26편 64,119 프레임 수동 라벨) | 렌더링 레시피는 얻을 수 없습니다 |

> 두 번째 항목이 시사점입니다. 우리는 **위치 검출**을 원하므로 블러를 줄이는 것이 맞지만, 훗날 속도를 블러에서 직접 얻고 싶어지면 노출을 **늘려야** 합니다. 목적이 상충합니다.

## 2. 블러 합성 방법

### 시간 초과표본화 + 누적

노출 구간 안에서 하위 프레임 N장을 렌더하고 평균합니다. 사실상의 표준 기법입니다.

**평균은 선형 공간에서 해야 합니다.** sRGB 감마 값을 그대로 평균하면 물리적으로 틀린 블러가 나옵니다 — 역 카메라 응답으로 선형화한 뒤 평균하고 다시 감마를 씌웁니다.

### 표본 수 부족의 증상

표본이 적으면 연속적인 블러가 아니라 **운동 방향으로 끊긴 고스팅**이 나타납니다. 정확한 필요 표본 수를 못 박은 문헌은 찾지 못했고, 블러 길이·속도·목표 품질에 따른다는 서술만 있습니다.

**실용 규칙: `N ≥ 블러 길이(px)`.** 하위 프레임 간 공 이동이 1 px 이하가 되어야 계단이 보이지 않습니다. 우리 최악 조건(1/60s, 106 px)에서 N = 128 정도면 충분합니다.

출처: [Motion Blur Rendering: State of the Art](https://graphics.unizar.es/papers/Navarro_motionblur.pdf), [Hybrid MBlur](https://arxiv.org/pdf/2210.06159)

### 확률적 표본화는 쓰지 않습니다

표본 시각을 무작위화하면 밴딩이 사라지지만 감당 가능한 표본 수에서 노이즈가 심합니다. 우리는 오프라인 생성이라 **균일 표본 + 충분한 N**이 맞습니다.

## 3. 합성 영상이 재현하지 못하는 것

| 항목 | 영향 |
|---|---|
| **롤링 셔터** | iPhone은 롤링 셔터입니다. 고속 수평 운동에서 공이 기울어 보입니다. 글로벌 셔터로 합성하면 이 왜곡이 없습니다 |
| 센서 노이즈·ISO 특성 | 1/1000s는 ISO를 끌어올리므로 실제로는 노이즈가 큽니다 |
| 렌즈 왜곡·비네팅 | 화각 주변 공 크기·밝기가 실제와 다릅니다 |
| 배경 복잡도 | 실제 코트는 관중·펜스·그림자가 있습니다 |

**합성 영상의 용도는 "도구가 동작하는가"와 "노출 가설의 방향이 맞는가"까지입니다.** 검출률 절대값을 합성으로 판정하면 안 됩니다 — 게이트 판정([프로토콜 5.5](../../02-설계/CAPTURE-PROTOCOL.md))은 실영상이어야 합니다.

## 4. #6에 반영할 것

- 하위 프레임 누적 방식, **선형 공간 평균**
- `N ≥ 블러 길이(px)`, 기본값은 최악 조건 기준으로 잡음
- 노출을 파라미터로 받아 위 표를 **합성 영상으로 재현**할 수 있어야 함 — 생성기 자체의 검증 수단이 됨
- 정답 JSON에 `blurLengthPx`를 포함 (논문 Eq. 8의 역산 검증용)
- 롤링 셔터 미구현을 기획서 "만들지 않을 것"에 명시
