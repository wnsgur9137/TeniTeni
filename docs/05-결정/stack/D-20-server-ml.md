# D-20. 서버 ML 스택

> **상태** ⏸ **보류 확정 — Phase 2 검증 후 결정** (2026-09-10) · **그룹** D. 백엔드

## 질문

서버 정밀 분석에 어떤 모델을 쓸 것인가? 애초에 필요한가?

## 후보

| 후보 | 메모 |
|---|---|
| TrackNetV2/V3 | 공 추적. 테니스 논문 표준 |
| MMPose (ViTPose/HRNet) | 고정밀 포즈 |
| MotionBERT 계열 | 2D→3D 리프팅 |
| 도입하지 않음 | 온디바이스로 충분하다면 |

## 잠정안

**미정**

## 쟁점

- **선결 조건: 서버 정밀 분석이 온디바이스 대비 유의미한 개선을 주는지 정량 검증**
- 차이가 작으면 서버 ML 자체를 축소하거나 제거한다. GPU 비용 대비 가치가 없다
- 이 결정이 GPU 필요 여부 → 인프라 비용을 결정한다

## 결정

**의도적으로 보류한다.** Phase 2를 **CPU 추론으로 시작**하고, 정량 검증 결과를 보고 도입 여부를 결정한다.

이것은 "아직 못 정했다"가 아니라 **"지금 정하지 않는 것이 옳다"는 결정**이다.

## 근거

- Phase 0에서 온디바이스 궤적 검출률을 재기 전에는 서버 ML의 **개선폭을 알 수 없다.** 지금 정하면 검증 전에 투자하는 셈이다
- **Phase 0 게이트를 통과하면(검출률 70%+) 서버 ML의 명분이 크게 줄어든다.** 온디바이스로 충분하다는 뜻이기 때문이다
- GPU 인스턴스는 상시 비용이 발생한다. 가치가 확인되기 전에 켜둘 이유가 없다

## Phase 2 판정 절차

1. 고정 샘플 영상 10개에 대해 온디바이스 분석 결과를 픽스처로 저장
2. 같은 영상을 서버 모델(TrackNetV2, ViTPose)로 분석
3. 비교 지표: 궤적 검출률, 임팩트 프레임 오차, 주요 관절 각도 편차
4. 판정
   - **개선폭이 작으면** → 서버 ML을 도입하지 않는다. 서버는 저장·집계·리포트만 담당 ([D-21](./D-21-deployment.md) 인프라가 크게 단순해짐)
   - **개선폭이 크면** → 해당 영역만 선별 도입. 워커를 GPU 인스턴스로 분리 ([D-17](./D-17-task-queue.md) 큐 라우팅 재검토 필요)

## 후보 (도입 시)

| 영역 | 후보 |
|---|---|
| 공 추적 | TrackNetV2 / V3 — 테니스·배드민턴 논문의 표준 |
| 정밀 포즈 | MMPose (ViTPose / HRNet) |
| 3D 리프팅 | MotionBERT 계열 |
| 코트 검출 | OpenCV Hough 또는 학습 기반 세그멘테이션 |
