# ADR-0001. 온디바이스/서버 하이브리드 추론 구조

- **상태**: Accepted
- **날짜**: 2026-09-10

## 맥락

TeniTeni는 카메라 영상에서 포즈와 공 궤적을 추정해야 합니다. 추론을 어디서 수행할지 결정해야 하며, 이 선택이 앱 구조, 백엔드 필요 여부, 개발 순서를 모두 결정합니다.

제약 조건:
- 테니스 코트는 네트워크 환경이 나쁘다 (야외, 지하, 공용 와이파이)
- 촬영 중 오버레이는 100ms만 늦어도 쓸모없다
- 개인 프로젝트이므로 서버 운영 비용과 개발 인력이 제한적이다
- 얼굴이 담긴 영상이라 프라이버시 민감도가 높다

## 검토한 선택지

### A. 전면 온디바이스
- ✅ 네트워크 불필요, 지연 없음, 프라이버시 우수, 서버 비용 0
- ❌ 모델 개선 시 앱 심사를 거쳐야 배포됨 (개선 루프가 주 단위)
- ❌ 프로 레퍼런스 라이브러리를 전부 기기에 넣을 수 없음
- ❌ 기기 간 동기화, 장기 진척도 추적 불가
- ❌ 무거운 모델(3D 리프팅, TrackNet)이 실시간 예산에 안 들어감

### B. 전면 서버
- ✅ 모델 자유롭게 교체, 정밀도 최대
- ❌ 실시간 오버레이 불가능 (스트리밍 지연)
- ❌ 데이터 비용, 코트 네트워크 환경에서 사용 불가
- ❌ GPU 서버 상시 운영 비용
- ❌ 모든 영상이 서버로 전송됨 (프라이버시)

### C. 하이브리드 — 실시간은 기기, 정밀 분석은 서버 비동기
- ✅ 실시간 요구를 만족하면서 서버의 이점도 확보
- ✅ 오프라인에서 핵심 기능이 동작 → **백엔드 없이 Phase 0/1 진행 가능**
- ✅ 업로드를 옵트인으로 두어 프라이버시 통제
- ❌ 두 개의 추론 경로를 유지해야 함 (결과 정합성 관리 필요)
- ❌ 구현 복잡도 증가

## 결정

**C. 하이브리드를 채택한다.**

- 실시간 레인(온디바이스): 촬영 중 오버레이, 스윙 검출, 즉시 피드백
- 정밀 레인(서버 비동기): 업로드된 클립의 재분석, 레퍼런스 비교, 리포트

**오프라인 우선 원칙**을 함께 확정합니다: 네트워크가 없어도 촬영과 리플레이는 완전히 동작해야 합니다. 서버는 부가 가치일 뿐 필수 경로가 아닙니다.

## 결과

**쉬워지는 것**
- Phase 0/1을 백엔드 없이 진행할 수 있어 기술 검증이 빨라진다
- 서버 장애가 핵심 기능을 막지 않는다
- 프라이버시 설계가 단순해진다 (기본값 = 업로드 안 함)

**어려워지는 것**
- 온디바이스 결과와 서버 결과가 다를 수 있다 → 어느 쪽을 보여줄지 규칙이 필요하다
  - 결정: 서버 분석이 완료되면 갱신하되, **로컬 결과를 지우지 않는다** (오프라인에서 계속 보여야 하므로)
- 메트릭 계산 로직이 Swift와 Python 양쪽에 존재하게 된다 → 골든 테스트로 양쪽 일치를 검증한다

**되돌리는 비용**: 중간. 전면 온디바이스로 축소하는 것은 쉽다(서버 경로를 끄면 됨). 전면 서버로 가는 것은 사실상 재작성이다.
