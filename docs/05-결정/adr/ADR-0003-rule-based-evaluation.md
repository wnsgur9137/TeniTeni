# ADR-0003. 자세 평가는 룰 엔진 우선, 학습형은 유보

- **상태**: Accepted
- **날짜**: 2026-09-10

## 맥락

"이 스윙이 좋은가 나쁜가"를 판정해야 합니다. 이것이 제품의 핵심 가치이자 가장 어려운 기술 과제입니다.

제약 조건:
- **점수가 라벨링된 테니스 스윙 데이터셋은 존재하지 않는다**
- 만들려면 코치 수십 명이 수천 개 영상을 채점해야 한다. 개인 프로젝트에서 불가능
- 프로 선수들의 폼은 서로 크게 다르다. **정답이 하나가 아니다**
- 사용자는 틀린 지적에 매우 민감하다. 한 번 신뢰를 잃으면 앱을 지운다

## 검토한 선택지

### A. 학습형 평가 모델 (스윙 → 점수)
- ✅ 성공하면 가장 자연스러운 UX
- ❌ 학습 데이터가 없다. 이것만으로 배제 사유가 충분하다
- ❌ 블랙박스라 "왜 낮은 점수인지" 설명할 수 없다 → 교정 앱으로서 치명적

### B. 룰 기반 (메트릭 → 권장 범위 비교)
- ✅ 데이터 불필요, 즉시 구현 가능
- ✅ **설명 가능하다.** "팔꿈치 112°, 권장 150~170°"는 그 자체로 피드백이다
- ✅ 코치 자문으로 임계값을 점진 개선할 수 있다
- ❌ 개인차·스타일 차이를 반영하지 못한다
- ❌ 권장 범위를 정하는 데 도메인 지식이 필요하다

### C. 레퍼런스 비교 (DTW로 프로 스윙과 정렬 후 편차 측정)
- ✅ 시각적으로 가장 설득력 있다 (고스트 오버레이)
- ✅ 라벨이 필요 없다. 레퍼런스 영상만 있으면 된다
- ❌ 체격 정규화, 시간축 정렬 등 선결 과제가 있다
- ❌ 어떤 프로를 기준으로 삼을지가 또 다른 문제

## 결정

**3단계 점진적 접근을 채택한다.**

1. **Phase 1 — 룰 기반 (B)**: 메트릭별 권장 범위를 정의하고 이탈 시 피드백 생성
2. **Phase 2~3 — 레퍼런스 비교 (C)**: DTW 정렬 + 고스트 오버레이로 시각적 비교 추가
3. **Phase 4+ — 학습형 (A)**: 사용자 데이터와 코치 피드백이 축적된 뒤에만 착수. **그 전까지는 착수하지 않는다**

### 피드백 UX 원칙 (함께 확정)

- **한 번에 하나**를 고치게 한다. 우선순위 1개를 크게 보여준다. 한 스윙에 최대 2~3개
- **원인이 아니라 동작**을 지시한다: "체중 이동이 부족합니다"(❌) → "앞발에 체중을 더 실어보세요"(⭕)
- **수치를 함께 보여준다**. 신뢰도가 올라가고 다음 촬영에서 개선을 확인할 수 있다
- **틀릴 수 있음을 인정한다**. 신뢰도가 낮으면 단정형으로 표현하지 않는다

## 결과

**쉬워지는 것**
- 데이터 수집 없이 Phase 1에서 제품을 완성할 수 있다
- 모든 피드백에 근거 수치가 붙어 설명 가능하다
- 임계값이 코드/설정에 명시되므로 코치 자문 결과를 즉시 반영할 수 있다

**어려워지는 것**
- 권장 범위를 정하는 도메인 작업이 필요하다 → **코치 자문 확보가 프로젝트의 실질적 선결 과제**
- 개인차를 반영하지 못해 일부 사용자에게 부정확할 수 있다 → 신뢰도 표기와 "이 지적 무시하기" 옵션으로 완화

**되돌리는 비용**: 낮음. 룰 엔진은 학습형 모델이 준비되면 보완/대체할 수 있고, 설명 레이어로 남겨두는 것도 가능하다.
