# 11. 디자인 시스템

목업·구현이 공유하는 단일 기준입니다. 여기 없는 값을 화면에서 즉흥으로 만들지 않습니다.

## 11.1 원칙

**1. 오버레이와 UI는 다른 팔레트를 쓴다**

이 앱만의 제약입니다. 스켈레톤 오버레이가 영상 위에 그려지는데, UI 강조색이 오버레이 색과 겹치면 **사용자가 "앱이 강조한 것"과 "몸에서 잘못된 것"을 구분하지 못합니다.**

```
오버레이 레이어 (영상 위)   시안 · 화이트 · 레드 · 앰버
UI 레이어 (그 위)          라임 · 오렌지 · 그린
```

**2. 다크 우선**

촬영 화면이 영상 위주라 밝은 UI가 영상을 방해합니다. 야외 직사광선에서는 대비가 관건이라 순수 검정보다 약간 밝은 배경을 씁니다.

**3. 6m 밖에서 읽혀야 하는 요소가 있다**

[IA-FLOW 10.5](IA-FLOW.md)의 제약. 촬영 중 카운트는 일반 UI 스케일로는 안 됩니다.

**4. 숫자는 흔들리지 않는다**

각도·카운트가 실시간으로 바뀌므로 **tabular figures**를 강제합니다. 안 그러면 숫자 폭이 변해 레이아웃이 떨립니다.

## 11.2 컬러

### 배경 · 표면

| 토큰 | 값 | 용도 |
|---|---|---|
| `bg/base` | `#0B0D0F` | 앱 배경 |
| `bg/surface` | `#16191D` | 카드, 시트, 패널 |
| `bg/elevated` | `#1F2429` | 표면 위 요소 |
| `bg/scrim` | `rgba(11,13,15,0.72)` | 영상 위 컨트롤 배경 |

### 텍스트

| 토큰 | 값 | 용도 |
|---|---|---|
| `text/primary` | `#F2F4F6` | 본문, 제목 |
| `text/secondary` | `#9BA3AB` | 보조 설명 |
| `text/tertiary` | `#6B737B` | 비활성, 힌트 |
| `text/on-accent` | `#0B0D0F` | 라임 배경 위 |

### 오버레이 팔레트 — 영상 위에만

| 토큰 | 값 | 의미 |
|---|---|---|
| `overlay/bone` | `rgba(255,255,255,0.72)` | 일반 본 |
| `overlay/racket-arm` | `#4DD8E6` 시안 | **라켓 잡은 팔** — 시선 유도 |
| `overlay/joint` | `#FFFFFF` | 관절 |
| `overlay/issue` | `#FF4D4D` 레드 | **문제 관절** |
| `overlay/trail` | `#FFD84D` 앰버 | 공 궤적 (공 색과 연결) |

본과 관절의 알파는 **관절 confidence를 그대로 매핑**합니다 ([SKELETON-OVERLAY 4.7](../02-설계/SKELETON-OVERLAY.md)). 가려진 관절이 흐려지면 사용자가 스스로 카메라 위치를 고칩니다.

### UI 팔레트 — 오버레이 위 레이어

| 토큰 | 값 | 용도 |
|---|---|---|
| `accent/primary` | `#C6F24E` 라임 | CTA, 선택 상태, 지시형 피드백 |
| `state/success` | `#3DDC84` | 개선, 정상 |
| `state/warning` | `#FF8A3D` 오렌지 | 흔들림·발열·조명 경고 |
| `state/error` | `#FF4D4D` | 오류 |
| `state/info` | `#4DD8E6` | 안내 |

> `state/error`와 `overlay/issue`, `state/info`와 `overlay/racket-arm`은 같은 값입니다. **의미가 같으므로 의도적으로 통일**했습니다 — 레드는 언제나 "문제", 시안은 언제나 "주목".

### 접근성

- 본문 텍스트 대비 **4.5:1 이상**, 큰 텍스트 4.5:1 이상 (야외 직사광선 고려해 AA보다 엄격하게)
- **색만으로 정보를 전달하지 않습니다.** 문제 관절은 색 + 크기 + 각도 라벨 3중으로 표시 — 적록색맹 대응
- 궤적 앰버와 라켓 팔 시안은 색상환에서 멀어 대부분의 색각 이상에서 구분됩니다

## 11.3 타이포그래피

시스템 폰트(SF Pro)를 씁니다. iOS 네이티브 앱에서 커스텀 폰트를 쓸 이유가 없고, Dynamic Type을 그대로 받습니다.

| 토큰 | 크기 / 굵기 | 용도 |
|---|---|---|
| `display/xl` | 72 / Bold | **촬영 중 스윙 카운트** — 6m 가독성 |
| `display/l` | 48 / Bold | 점수, 주요 수치 |
| `title/l` | 28 / Semibold | 화면 제목 |
| `title/m` | 22 / Semibold | 섹션 제목 |
| `body/l` | 17 / Regular | **지시형 피드백** |
| `body/m` | 15 / Regular | 본문 |
| `caption` | 13 / Regular | 보조 설명, 근거 수치 |
| `micro` | 11 / Medium | 라벨, 배지 |

### 수치 표기

각도·카운트·시간은 **`font-variant-numeric: tabular-nums`** 를 강제합니다. SwiftUI에서는 `.monospacedDigit()`.

| 종류 | 형식 | 예 |
|---|---|---|
| 각도 | 정수 + `°` | `112°` |
| 범위 | `권장 N~M°` | `권장 150~170°` |
| 카운트 | 정수 | `34` |
| 시간 | `m:ss` | `12:04` |
| 속도 | 정수 + `km/h` | `98km/h` |

## 11.4 간격 · 형태

**4의 배수**를 씁니다.

```
4  8  12  16  20  24  32  40  48  64
```

| 토큰 | 값 | 용도 |
|---|---|---|
| `radius/sm` | 6 | 배지, 칩 |
| `radius/md` | 10 | 버튼, 입력 |
| `radius/lg` | 14 | 카드 |
| `radius/xl` | 20 | 시트, 모달 |
| `radius/full` | 999 | 원형 버튼 |

**터치 타깃은 최소 44×44**입니다. 촬영 화면의 녹화 버튼은 64입니다 — 장갑 낀 손이나 급하게 누를 때를 고려합니다.

## 11.5 피드백 표현 — 신뢰도로 나눈다

[IA-FLOW 10.6](IA-FLOW.md)의 확정 사항을 시각으로 옮깁니다.

### 지시형 — 신뢰도 높음

룰 임계를 확실히 벗어났고 관절 confidence도 충분할 때.

```
┌────────────────────────────────┐
│  앞발에 체중을 더 실어보세요      │  body/l · text/primary
│  112° · 권장 150~170°           │  caption · text/secondary
└────────────────────────────────┘
   accent/primary 좌측 4px 바
```

### 제시형 — 신뢰도 낮음

임계 근처이거나, 관절 confidence가 낮거나, 표본이 부족할 때.

```
┌────────────────────────────────┐
│  임팩트 시 팔꿈치 112°입니다.     │  body/m · text/secondary
│  권장 범위는 150~170°입니다.      │
└────────────────────────────────┘
   text/tertiary 좌측 4px 바
```

**차이는 세 가지**입니다 — 문장 형태(지시 vs 서술), 타이포 위계, 좌측 바 색. 배경색은 같습니다. 제시형을 시각적으로 "약하게" 만들되 "경고"처럼 보이면 안 됩니다.

## 11.6 상태 표현

### 촬영 중 — 화면 테두리

6m 밖에서 읽혀야 하므로 **화면 가장자리 전체**를 씁니다.

| 상태 | 테두리 |
|---|---|
| 정상 | 없음 |
| 경고 (흔들림·조명·발열) | `state/warning` 3px |
| 오류 (인식 실패·저장공간) | `state/error` 3px + 펄스 |

### 스윙 감지

시각보다 **소리가 주**입니다 ([IA-FLOW 10.5](IA-FLOW.md)). 화면에서는 카운트 숫자가 한 번 스케일 업(1.0 → 1.15 → 1.0, 180ms)합니다.

## 11.7 SwiftUI 매핑

`DesignSystem` 모듈 구현 시 이 구조를 따릅니다 ([WORK-PLAN 9.6](../04-계획/WORK-PLAN.md)에서 1-A에 도입).

```
DesignSystem/Sources/
├── Tokens/
│   ├── Color+Token.swift      // bg/text/overlay/accent/state
│   ├── Font+Token.swift       // display/title/body/caption/micro
│   ├── Spacing.swift          // 4의 배수 상수
│   └── Radius.swift
├── Components/
│   ├── FeedbackCard.swift     // 지시형/제시형 분기
│   ├── MetricLabel.swift      // tabular figures 강제
│   ├── PhaseScrubber.swift
│   └── ModeSelector.swift
└── Modifiers/
    └── StatusBorder.swift     // 촬영 중 테두리
```

**오버레이 색은 `DesignSystem`이 아니라 `TeniVision`에 둡니다.** `SkeletonStyle`이 이미 그 자리이고, 렌더 패스가 참조하므로 UI 모듈에 의존시키면 안 됩니다 ([WORK-PLAN 9.6](../04-계획/WORK-PLAN.md)의 의존성 방향). 값은 이 문서를 기준으로 동기화합니다.

## 11.8 하지 않는 것

- **가짜 iOS 상태 바를 그리지 않습니다.** 실제 기기에서 진짜 상태 바가 위에 렌더되어 겹쳐 보입니다
- **이모지를 UI에 쓰지 않습니다.** 아이콘은 인라인 SVG 또는 SF Symbols
- **그라디언트 남용을 피합니다.** 영상 위 스크림 외에는 평면 색
- 라운드 코너 + 좌측 컬러 바 조합을 남발하지 않습니다 — 피드백 카드에만 씁니다
